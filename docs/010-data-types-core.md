# 010 - Data Types Core

Цель задачи: Определить базовые типы данных для работы с ордербуком (LOB). Эти структуры станут «контрактом» между WebSocket-парсером, механизмом сохранения данных (Dumper) и Python-пайплайном (Parquet). Мы ориентируемся на 50 уровней стакана, что является стандартом для Bybit и оптимально для LiT-моделей.

src/data/types.rs: Создать структуры для хранения уровней и обновлений стакана. Использовать f64 для цен и объемов для совместимости с ML-библиотеками.

use serde::{Deserialize, Serialize};

/// Один уровень в стакане (цена + объем)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct PriceLevel {
    pub price: f64,
    pub size: f64, // объем (volume)
}

/// Обновление или полный снапшот стакана от Bybit
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct OrderBookUpdate {
    pub symbol: String,
    pub timestamp_ms: u64,      // ts события от биржи
    pub last_update_id: u64,    // 'u' или 'seqNum' для проверки последовательности
    pub is_snapshot: bool,      // true для полного снимка, false для дельты (update)
    pub bids: Vec<PriceLevel>,  // Лимиты на покупку (динамический размер, до 50 уровней)
    pub asks: Vec<PriceLevel>,  // Лимиты на продажу (динамический размер, до 50 уровней)
}

Технические требования:

Типы: f64 для цен/объемов. Несмотря на возможные ошибки округления, для нормализации в ML это стандарт.
Сериализация: Обязательно Serialize и Deserialize для корректной работы с Parquet и передачи данных в Python-часть проекта.
Метаданные: Поля last_update_id и is_snapshot критически важны для будущей логики сборки стакана из дельт (задача 014) и валидации целостности данных.
Глубина: Мы используем подписку orderbook.50, поэтому Vec будет содержать до 50 элементов. Дополнительная обрезка в типах не требуется.
Почему это важно: Это определение «сырых» данных. Мы намеренно не включаем сюда сделки (Trades) на данном этапе, фокусируясь исключительно на LOB (Limit Order Book) для реализации Фазы 2. Точное следование формату Bybit V5 позволит избежать ошибок при парсинге WebSocket-сообщений.
