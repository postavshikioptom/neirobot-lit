# **Задача №178: Динамическое сокращение лимитов позиции (Position Limit Dynamic Reduction)**

**Цель**: Реализация адаптивного управления капиталом путем расширения логики задачи [105](./docs/000-tasks_list.md). Бот должен автоматически снижать максимально допустимый размер позиции (`max_position_size`) при росте просадки (**Drawdown**) и рыночной волатильности, а также плавно восстанавливать лимиты после выхода из опасных зон для предотвращения "мести рынку".

---

## **План реализации для Gemini AI Coder:**

### **1. Изменения в [./src/config/types.rs](./src/config/types.rs)**
Добавить параметры в `RiskConfig` (изоляция **per-bot**):
- **`drawdown_scaling_start_pct`**: `f64` (просадка, при которой начинается сокращение лимитов, например 5.0%).
- **`volatility_threshold`**: `f64` (коэффициент превышения медианной волатильности, например 1.5).
- **`min_scale_factor`**: `f64` (минимальный порог сокращения, например 0.2 — не менее 20% от базы).
- **`recovery_rate`**: `f64` (скорость восстановления лимитов, например 0.05 / 5% в час или на сделку).

### **2. Расчет волатильности в [./src/risk/health_monitor.rs](./src/risk/health_monitor.rs)**
Добавить механизм отслеживания рыночной активности (источник для волатильности):
- **Метод**: Использовать `VecDeque<f64>` для хранения последних 100 изменений `mid_price` (абсолютные дельты или доходности).
- **`current_vol`**: Среднее абсолютное отклонение (MAD) или стандартное отклонение за последние 15 минут.
- **`hist_vol`**: Медианное значение волатильности за 24 часа (якорь).

### **3. Логика в [./src/risk/risk_manager.rs](./src/risk/risk_manager.rs)**
Реализовать расчет `effective_max_pos`:
- **Drawdown Scaling (Linear)**:
    - `f_dd = 1.0 - (current_drawdown - start) / (max_dd - start) * (1.0 - min_factor)`.
    - Источник `current_drawdown`: Из `PositionManager` (задачи [064](./docs/000-tasks_list.md), [070](./docs/000-tasks_list.md)).
- **Volatility Scaling (Inverse)**:
    - `vol_ratio = current_vol / hist_vol`.
    - `f_vol = if vol_ratio > threshold { 1.0 / vol_ratio } else { 1.0 }`.
- **Итоговый множитель**: `target_scale = f64::min(f_dd, f_vol).clamp(min_factor, 1.0)`.

### **4. Механизм плавного восстановления (Recovery Hysteresis)**
- **Асимметрия**: Лимиты сокращаются мгновенно при росте риска, но восстанавливаются плавно.
- **Логика**: 
  ```rust
  self.current_scale = if target_scale < self.current_scale {
      target_scale // Мгновенное сокращение
  } else {
      f64::min(target_scale, self.current_scale + config.recovery_rate) // Плавный рост
  };
  ```

### **5. Интеграция в гейты риска**
- В методе `check_position_limits` использовать `base_max_pos * current_scale`.
- Если сигнал требует объем больше текущего адаптивного лимита — возвращать `RiskError::DynamicLimitExceeded`.

### **6. Тестирование в [./tests/risk_gates.rs](./tests/risk_gates.rs)**
- **Volatility Spike**: Симулировать всплеск волатильности в 3 раза. Проверить, что лимит упал до 33%.
- **Drawdown Recovery**:
    1. Установить просадку 8% (лимит упал).
    2. Сбросить просадку до 0% (тейк-профит).
    3. Проверить, что `current_scale` не прыгнул в 1.0 сразу, а вырос лишь на `recovery_rate`.

## **Аргументы и обоснование (сопор с Grok):**
1. **Объединение с 105**: Мы не плодим сущности, а расширяем задачу 105 (Sizing), добавляя в неё фактор просадки. Это делает управление риском централизованным.
2. **Источник волатильности**: Использование изменений `mid_price` в `HealthMonitor` позволяет получать "быструю" волатильность без необходимости парсить тяжелые свечи (Candles), что сохраняет низкую латентность.
3. **Обратная волатильность (Inverse Vol)**: Формула `1 / vol_ratio` — стандарт индустрии для Target Volatility стратегий. Она гарантирует, что риск в долларах на сделку остается примерно постоянным.
4. **Hysteresis (Гистерезис)**: Плавное восстановление критически важно для предотвращения психологических и технических "срывов" (Revenge Trading) сразу после периода убытков.
