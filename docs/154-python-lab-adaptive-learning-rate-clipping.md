# Задача №154: Адаптивное ограничение градиентов (Adaptive Gradient Clipping — AGC)

Согласно [./docs/000-tasks_list.md](./docs/000-tasks_list.md), работа с данными стакана (LOB) на волатильных парах требует защиты от взрывных градиентов. Мы внедрим **AGC**, чтобы стабилизировать обучение Трансформера (LiT), особенно в моменты резких рыночных импульсов.

## План реализации для Gemini AI Coder:

### 1. Реализация логики AGC в [./python_lab/src/utils.py](./python_lab/src/utils.py)
Создать функцию `adaptive_gradient_clipping(model, clip_factor=0.01, eps=1e-6)`.
- **Алгоритм**: Для каждого параметра вычисляется отношение нормы градиента к норме весов: $\|G\| / \|W\|^*$. Где $\|W\|^* = \max(\|W\|, \epsilon)$.
- **Исключения (Важно)**: Согласно практике (NFNet/HF), **не применять** AGC к одномерным параметрам: `bias`, `LayerNorm` (веса и смещения) и `embeddings`. Ограничивать только многомерные весовые матрицы (`p.ndim > 1`).
- **Формула масштабирования**: Если ratio > `clip_factor`, то $G = G \cdot \frac{clip\_factor \cdot \|W\|^*}{\|G\|}$.

### 2. Обновление [./python_lab/scripts/train.py](./python_lab/scripts/train.py)
Интегрировать выбор режима клиппинга через CLI.
- **Аргументы**:
    - `--clip_mode`: `none`, `norm` (стандартный по всей модели), `agc` (адаптивный послойный).
    - `--clip_val`: порог (для `norm` обычно 1.0, для `agc` в диапазоне 0.01-0.1).
- **Цикл обучения**:
    ```python
    loss.backward()
    if args.clip_mode == 'agc':
        utils.adaptive_gradient_clipping(model, clip_factor=args.clip_val)
    elif args.clip_mode == 'norm':
        torch.nn.utils.clip_grad_norm_(model.parameters(), args.clip_val)
    optimizer.step()
    ```

### 3. Мониторинг в [./python_lab/src/utils.py](./python_lab/src/utils.py)
Добавить расширенную диагностику градиентов:
- **`log_grad_stats`**: Считать и выводить в лог:
    - Процент параметров, к которым был применен клиппинг.
    - Максимальное значение отношения $\|G\| / \|W\|$ среди слоев внимания (Attention).
- **Цель**: Понять, не "задыхается" ли модель от слишком жесткого ограничения.

### 4. Интеграция с Optuna (см. задачу 030)
- Добавить `clip_val` в пространство поиска. 
- **Гипотеза**: Для инструментов с высокой плотностью ордеров (BTC) нужен более мягкий клиппинг, для "щиткоинов" (PEPE/FART) — более агрессивный (меньший `clip_factor`).

### 5. Безопасность (Epsilon)
- Использовать `eps=1e-6` вместо 1e-3, чтобы избежать чрезмерного подавления градиентов у разреженных или малых по значению весов, что критично для первых слоев Patching.

## Аргументация (Спор с Grok):
- **Согласен**: Переименование задачи в `adaptive-gradient-clipping` необходимо для исключения путаницы с Learning Rate Schedulers.
- **Согласен**: Исключение `LayerNorm` и `bias` из AGC — критический момент. Эти параметры отвечают за калибровку активаций, и их жесткий клиппинг может привести к "затуханию" обучения.
- **Согласен**: `eps=1e-6` — более стандартное значение, предотвращающее деление на ноль без искажения масштаба градиентов.
