Задача 051-python-lab-implement-mcc-metric.md
Цель: Реализовать комплексную систему оценки качества модели, включающую MCC, Balanced Accuracy и поклассовые метрики (Precision, Recall, F1), для работы в условиях сильного дисбаланса классов стакана.

Инструкции для Gemini:
1. Изменения в ./python_lab/src/utils.py
Функция compute_metrics(y_true, y_pred):
Используйте sklearn.metrics.
MCC: matthews_corrcoef(y_true, y_pred).
Balanced Accuracy: balanced_accuracy_score(y_true, y_pred).
Per-class Metrics: Используйте classification_report(y_true, y_pred, output_dict=True) для извлечения Precision, Recall и F1 для каждого из 3-х классов (0, 1, 2).
Macro F1: Добавьте среднее значение F1 (f1_score с average='macro').
Возврат: Функция должна возвращать плоский словарь для удобного логирования:
{
    "mcc": 0.25,
    "balanced_acc": 0.60,
    "f1_up": 0.15,
    "f1_down": 0.14,
    "f1_flat": 0.92,
    "f1_macro": 0.40
}
2. Изменения в ./python_lab/scripts/train.py
Интеграция в Val Loop: Вычисляйте метрики после каждой эпохи на всем валидационном наборе.
Логирование:
Выводите в консоль: MCC, Macro-F1 и Balanced Acc.
Поклассовые метрики пишите в подробный лог (или TensorBoard).
Логика сохранения и остановки:
Early Stopping: Должен отслеживать val_loss (как более стабильный и дифференцируемый показатель).
Best Model Checkpoint: Сохраняйте "лучшую" модель, ориентируясь на MCC или Macro-F1 (выберите одно, MCC предпочтительнее для LOB).

Мои аргументы в пользу этого плана:
Поклассовый F1: Позволит сразу увидеть "коллапс модели", если она начнет предсказывать только Flat (в этом случае F1 для Up/Down обнулится).
Balanced Accuracy: Хорошее дополнение к MCC, показывающее среднюю точность по классам без учета их веса в выборке.
Безопасность обучения: Остановка по val_loss предотвращает преждевременный выход из-за шума в метриках на маленьких валидационных выборках.
Критическое требование: Убедитесь, что метрики считаются на CPU после переноса тензоров с GPU (.detach().cpu().numpy()), чтобы не вызывать утечек памяти.
