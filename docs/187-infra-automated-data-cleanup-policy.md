# **Задача №187: Политика автоматизированной очистки данных (Automated Data Cleanup Policy)**

**Цель**: Предотвращение исчерпания дискового пространства путем автоматического удаления устаревших рыночных данных (Raw Data). Бот должен управлять накоплением Parquet/CSV файлов в директории `bots/SYMBOL/data/raw/`, соблюдая баланс между глубиной истории для обучения и физическими лимитами диска.

---

## **План реализации для Gemini AI Coder:**

### **1. Изменения в [./src/config/types.rs](./src/config/types.rs)**
Добавить параметры в структуру `HealthCheckConfig` (изоляция **per-bot**):
- **`raw_data_retention_days`**: `u32` (срок хранения снимков стакана и сделок, например 14 дней).
- **`max_data_dir_size_gb`**: `u64` (жесткий лимит объема папки `data/`, например 50 ГБ).
- **`cleanup_interval_hours`**: `u32` (периодичность проверки, например 12 часов).

### **2. Реализация в [./src/risk/health_monitor.rs](./src/risk/health_monitor.rs)**
Добавить метод `perform_data_cleanup()`, выполняемый в `tokio::spawn_blocking`:

#### **А. Очистка по времени (Retention)**
- Сканировать директорию [./bots/SYMBOL/data/raw/](./bots/SYMBOL/data/raw/).
- Удалять файлы, время последней модификации которых старше `raw_data_retention_days`.

#### **Б. Очистка по квоте (Size Quota)**
- Если суммарный размер директории превышает `max_data_dir_size_gb`:
    - Сортировать файлы по времени создания (от старых к новым).
    - Удалять файлы по одному (FIFO), пока объем не станет ниже лимита.
- **Защитный буфер**: Никогда не удалять данные за последние 24 часа, даже при превышении квоты (для обеспечения возможности экстренного дообучения модели).

### **3. Интеграция в жизненный цикл**
- Инициализировать периодический таймер в `run_periodic_checks` (задача [171](./docs/171-risk-manager-system-health-sanity-check.md)).
- Обеспечить неблокирующее выполнение операций с файловой системой, чтобы не вносить задержки в торговый цикл.

### **4. Логирование результатов**
- Записывать в лог итоги каждой итерации: `[Health] Data cleanup finished. Freed: 12.4 GB, Deleted files: 156`.
- Выводить `warn!`, если не удается получить доступ к файлам или рассчитать размер папки.

---

## **Аргументация и обоснование:**
1. **Изоляция данных**: Механизм работает на уровне конкретного бота, что предотвращает влияние активности одного токена на дисковые квоты других.
2. **Безопасность (24h Buffer)**: Наличие данных за последние сутки критично для оперативного анализа инцидентов и валидации сигналов в `python_lab`.
3. **FIFO логика**: Приоритетное удаление самых старых данных при превышении квоты — наиболее эффективный способ сохранения актуальной истории для ML-пайплайна.
4. **Отсутствие оверхеда**: Использование `spawn_blocking` гарантирует, что тяжелые операции сканирования диска не повлияют на задержки (Latency) инференса модели.
