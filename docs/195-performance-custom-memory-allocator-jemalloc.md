# Задача №195: Оптимизация производительности: Кастомный аллокатор памяти для Windows (mimalloc)

[./docs/195-performance-custom-memory-allocator-mimalloc.md](./docs/195-performance-custom-memory-allocator-mimalloc.md)

## План реализации для Gemini

1.  **Изменения в зависимостях**:
    - Добавить в `Cargo.toml` крейт `mimalloc = "0.1"`. Этот аллокатор разработан Microsoft и показывает лучшие результаты производительности именно в среде Windows (MSVC) по сравнению со стандартным системным аллокатором.

2.  **Интеграция в [./src/bin/run-bot.rs](./src/bin/run-bot.rs)**:
    - Установить `mimalloc` в качестве глобального аллокатора памяти.
    - Использовать атрибут `#[global_allocator]` и ограничить его применение только платформой Windows через `#[cfg(windows)]`.
    - Пример реализации:
      ```rust
      #[cfg(windows)]
      #[global_allocator]
      static GLOBAL: mimalloc::MiMalloc = mimalloc::MiMalloc;
      ```

3.  **Тюнинг производительности**:
    - В `Cargo.toml` настроить фичи `mimalloc`, например, отключить `secure` режим для достижения максимальной скорости аллокаций, если это допустимо требованиями безопасности.

4.  **Оптимизация под Windows**:
    - Убедиться, что при сборке через `cargo build --release` линковка происходит корректно. Кастомный аллокатор позволит снизить фрагментацию памяти и ускорить работу с `Vec` и `HashMap` в "горячих" точках (обработка обновлений стакана и расчет фичей).

## Ожидаемый результат
- Снижение задержек (P99 latency) при интенсивной работе с памятью в среде Windows.
- Более эффективное управление кучей (heap) и уменьшение системных вызовов аллокации.
- Отсутствие влияния на другие ОС благодаря использованию условной компиляции `#[cfg(windows)]`.
