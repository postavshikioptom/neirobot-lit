Задача 069: Реализация логики Post-Only ордеров
Цель: Внедрить поддержку режима Post-Only для минимизации комиссий, реализовав алгоритм немедленного переставления ордера при отклонении биржей.

Инструкции для реализации:
1. Изменения в ./src/config/types.rs
Добавить в BotConfig параметры:
post_only: bool (по умолчанию true).
post_only_retry_limit: u32 (количество быстрых попыток переставления, например 3).
2. Изменения в ./src/trading/order_manager.rs
Контроль статусов: В методе update_order_state (из ./068-trading-order-manager-track-lifecycle.md) добавить распознавание причины отмены:
Если status == Cancelled и cancelType == "CancelByPostOnly" (или соответствующий retCode), пометить ордер как PostOnlyRejected.
3. Изменения в ./src/trading/execution.rs
Логика "Умного" выставления цены:
При post_only = true для Buy устанавливать цену price = best_bid.
Для Sell устанавливать цену price = best_ask.
Опционально: Добавить микро-отступ (offset) в 1 tick_size для гарантированного попадания в очередь (Maker).
Обработка отказа (Immediate Retry):
Если ордер отклонен по причине PostOnly, и лимит post_only_retry_limit не исчерпан:
Получить актуальный best_bid/ask из стакана.
Немедленно отправить новый ордер по обновленной цене.
Обработка застоя (Timeout):
Если ордер принят (статус New), но не исполнился за limit_timeout_ms (из ./058-python-lab-backtest-slippage-model.md):
Отменить текущий Post-Only лимит.
Выставить Market-ордер (или GTC лимит) для гарантированного входа/выхода по вашему требованию.
4. Логирование
debug!("Post-Only rejected for {}. Retrying with new price...", symbol).
warn!("Post-Only retries exhausted or timeout reached. Falling back to Market/GTC.").
Аргументация изменений:
Разделение причин: Отказ Post-Only происходит мгновенно (в момент обработки ордера биржей). Выход по тайм-ауту происходит спустя секунды. Это разные сценарии, требующие разной скорости реакции.
Экономика Maker: Мы боремся за каждый ордер, чтобы он стал Maker-ом. Быстрое переставление цены (re-pegging) при отклонении позволяет "зацепиться" за край стакана без уплаты Taker-комиссии.
Гарантия исполнения: Гибридная модель (сначала пробуем дешево через Post-Only, затем гарантированно через Market) — это баланс между экономией и необходимостью быть в позиции.
Критическое требование: Убедиться, что при расчете новой цены для retry используется tick_size из MarketInfo (задача 065), чтобы цена всегда была кратна шагу биржи.
