# Задача №157: Экспорт квантованной модели (INT8) в ONNX

Согласно [./docs/000-architecture.md](././docs/000-architecture.md), мы стремимся к максимальной производительности Rust-бота. Переход от **FP32** к **INT8** позволит кратно ускорить инференс на CPU за счет использования инструкций AVX-512/VNNI.

## План реализации для Gemini AI Coder:

### 1. Подготовка данных для калибровки в [./python_lab/src/dataset.py](./python_lab/src/dataset.py)
Для статического квантования (PTQ) необходим репрезентативный набор данных для калибровки диапазонов активаций.
- **Calibration Set**: 500-1000 снапшотов из валидационной выборки.
- **Data Reader**: Реализовать класс `LOBDataLoader(CalibrationDataReader)`, который через `next()` возвращает словарь `{'input_name': batch_tensor.numpy()}`.
- **Важно**: Имя входного тензора (`input_name`) извлекать динамически из `onnx_model.graph.input[0].name`.

### 2. Скрипт квантования [./python_lab/scripts/quantize_onnx.py](./python_lab/scripts/quantize_onnx.py)
Создать инструмент на базе `onnxruntime.quantization.quantize_static`.
- **Настройки квантования**:
    - **Activations**: `QuantType.QInt8` (symmetric).
    - **Weights**: `QuantType.QUInt8` (asymmetric) с обязательным флагом `per_channel=True` для сохранения точности Трансформера.
- **CLI Аргументы**:
    - `--input`: путь к FP32 модели.
    - `--output`: путь к `lit_int8.onnx`.
    - `--max_mcc_drop`: (default 0.02) порог допустимой потери качества.

### 3. Автоматическое исключение узлов (Auto-Exclude)
Реализовать логику контроля качества:
1. Замерить **Baseline MCC** на FP32 модели.
2. Выполнить квантование.
3. Если падение MCC превышает `--max_mcc_drop`, скрипт должен автоматически добавить проблемные узлы (обычно это `Softmax`, `LayerNorm` или финальный `Linear` слой) в список `NodesToExclude` и повторить процесс.

### 4. Статистический бенчмарк в Python
Добавить процедуру замера производительности:
- **Warmup**: 1000 холостых прогонов.
- **Measurement**: 1000 итераций инференса.
- **Метрики**: Вывод `mean` и `std` латентности для обеих версий модели (FP32 vs INT8).

### 5. Интеграция в Rust и Конфиги
- **Конфиг**: Обновить [./bots/CAKEUSDT/config.toml](./bots/CAKEUSDT/config.toml) (пример), указав `model_path = "model/lit_int8.onnx"`.
- **Код**: В [./src/ml/onnx.rs](./src/ml/onnx.rs) (задача 036) убедиться, что `SessionOptions` настроены на `optimize_graph = true` и корректно используют `CPUExecutionProvider` (или `CUDA` с TensorRT для INT8).

## Аргументация (Спор с Grok):
- **Согласен**: Использование `QUInt8` с `per_channel=True` для весов — это "золотой стандарт" для сжатия Трансформеров, позволяющий избежать деградации точности на специфических весах внимания.
- **Согласен**: Динамическое получение `input_name` из графа модели делает скрипт универсальным для любых изменений в `lit_model.py`.
- **Согласен**: `max_mcc_drop` должен быть настраиваемым, так как для разных инструментов (BTC vs PEPE) цена ошибки (false signal) может быть разной.
