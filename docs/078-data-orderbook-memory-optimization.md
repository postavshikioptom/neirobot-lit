Задача 078: Оптимизация памяти и производительности OrderBook (SmallVec + Stack)
Цель: Снизить нагрузку на аллокатор (heap) и ускорить обработку обновлений за счет использования SmallVec (хранение данных на стеке для типичных глубин) и оптимизации алгоритмов вставки/сортировки.

1. Изменения в Cargo.toml
Добавить зависимость: smallvec = "1.13" (актуальная версия для 2026).
Для бенчмарков: criterion = "0.5" (в [dev-dependencies]).
2. Изменения в ./src/data/orderbook.rs
Рефакторинг структуры OrderBook: Заменяем BTreeMap на SmallVec, чтобы уровни до 64 (Bybit обычно шлет 50) хранились на стеке без аллокации в куче.
use smallvec::SmallVec;

pub struct OrderBook {
    pub symbol: String,
    // Уровни (Price, Vol). Резервируем 64 элемента на стеке.
    bids: SmallVec<[(Decimal, Decimal); 64]>, 
    asks: SmallVec<[(Decimal, Decimal); 64]>,
    max_depth: usize,
}
Оптимизация логики обновления (apply_update_batch): Bybit присылает пакет (batch) дельт, который не всегда отсортирован.
Binary Search: Для каждой дельты в пакете использовать binary_search_by для поиска позиции.
bids.binary_search_by(|&(p, _)| target_price.cmp(&p)) (для bids — descending).
asks.binary_search_by(|&(p, _)| p.cmp(&target_price)) (для asks — ascending).
In-place Logic:
Найдено + объем > 0: Обновить vol на месте.
Найдено + объем == 0: SmallVec::remove(index).
Не найдено + объем > 0: SmallVec::insert(index, (price, vol)).
Efficiency: Для N=50..200 сдвиг элементов в SmallVec (память на стеке/непрерывный блок) значительно быстрее перестроения дерева или полной пересортировки.
Capacity: В new() делать reserve(max_depth * 2) для предотвращения реаллокаций при всплесках дельт.
3. Интеграция с тензором и контрольной суммой
Zero-copy Tensor Builder: В методе конвертации (задача 035) реализовать итератор, который напрямую применяет нормализацию: ((p - mid)/mid, log(v+1)) и записывает результат в f32 слайс для ONNX. Без промежуточных Vec.
Checksum parity: Убедиться, что порядок элементов в SmallVec строго соответствует алгоритму CRC32 из задачи 049 (Bids: high to low, Asks: low to high).
4. Почему этот план лучше (Аргументы Grok):
SmallVec: Большинство обновлений Bybit (depth 50) будут обрабатываться вообще без обращения к аллокатору кучи. Это радикально снижает фрагментацию памяти.
O(N) vs O(log N): Хотя вставка в Vec — это O(N), для малых N (до 500) она обходит BTreeMap за счет локальности кэша (CPU cache-friendly) и отсутствия разыменования указателей узлов.
Batch Integrity: Применение дельт через binary_search + insert сохраняет вектор отсортированным после каждой вставки, что критично для немедленного расчета контрольной суммы.
5. Тестирование и бенчмарки
Bench (Criterion): Написать тест, имитирующий реальный поток дельт Bybit (5-10 уровней в пакете). Сравнить alloc count.
Fuzzing: Подать 100 000 случайных дельт и сравнить итоговое состояние с эталонной реализацией на BTreeMap.
Checksum Test: Проверить, что оптимизированная структура проходит валидацию Bybit Checksum (задача 049).
