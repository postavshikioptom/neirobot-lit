Задача 089: Тестирование иерархии и валидации конфигураций
Цель: Гарантировать корректность работы кастомного загрузчика конфигураций (ConfigLoader). Проверить логику ручного слияния (merge) уровней настроек и работу валидаторов (Task 007).

1. Изменения в Cargo.toml
Добавить в [dev-dependencies]:
tempfile = "3.10" (для создания временных конфигов).
toml = "0.8" (уже в проекте, для генерации тестовых данных).
2. Архитектура тестов
Файл: ./tests/config_tests.rs.
Метод: Использование tempfile для создания трех файлов: global.toml, exchange.toml и bot.toml. Проверка результата вызова ConfigLoader::load().
3. Тестовые сценарии (Scenarios)
Ручное слияние (Manual Merge):
global.toml: max_spread_bps = 50, ws_ping_interval = 20.
exchange.toml: max_spread_bps = 25.
bot.toml: max_spread_bps = 10.
Assert: Финальное значение max_spread_bps для бота должно быть 10, а ws_ping_interval должен унаследоваться от глобального (20).
Обработка Option-полей:
Проверить, что если поле в bot.toml равно None (отсутствует), оно корректно берет значение из exchange.toml или global.toml.
Валидация бизнес-логики (Task 007):
Положительные значения: Попробовать загрузить max_open_orders = -5 или max_spread_bps = 0. Assert: Ошибка валидации.
Существование путей: Подать несуществующий путь в model_path. Assert: Ошибка Path does not exist.
Формат символа: Подать symbol = "cake-usdt". Assert: Ошибка формата (ожидается CAKEUSDT).
Синтаксические ошибки:
Подать файл с невалидным TOML (пропущенные кавычки и т.д.). Assert: Result::Err с указанием строки ошибки.
Environment Overrides (Secrets):
Установить переменную окружения BYBIT_API_KEY.
Assert: Проверить, что метод load_secrets() (задача 061) отдает приоритет переменной окружения перед файлом .env.
4. Почему этот план лучше (Аргументы Grok):
No Figment: Мы тестируем именно тот код, который написали вручную в задачах 005-006 (используя toml::from_str и merge), что исключает скрытое поведение внешних библиотек.
Custom Validation: В отличие от простого парсинга, мы проверяем "бизнес-правила" (Task 007), которые критичны для торговой логики.
Single Bot Isolation: Тесты подтверждают архитектуру, где каждый бот имеет свой изолированный конфиг, и настройки одного не могут случайно переопределить настройки другого (отсутствие глобальных списков ботов).
Tempfile Cleanup: Автоматическое удаление тестовых конфигов после прохождения тестов предотвращает мусор в репозитории.
5. Критические требования
No Panics: Загрузчик обязан возвращать anyhow::Result.
Exact Match: Использовать assert_eq! для всех полей результирующей структуры.
Default Traits: Проверить, что если файлы exchange/global отсутствуют, бот может запуститься на дефолтных значениях (если это предусмотрено).
6. Запуск
cargo test --test config_tests
