Задача 059-python-lab-backtest-fee-logic.md
Цель: Внедрить точный расчет комиссий для гибридной модели исполнения, обеспечив реалистичную оценку чистой прибыли (Net PnL).

Инструкции для реализации:
1. Изменения в ./python_lab/scripts/backtest.py
Параметры CLI (с учетом реализма):
--maker_fee_bps: по умолчанию 2.0 (0.02%). Ниже этого значения не опускаться для надежности.
--taker_fee_bps: по умолчанию 5.5 (0.055%).
Интеграция с результатами исполнения (из задачи 058):
Для каждой сделки (Roundtrip: Вход + Выход) скрипт должен отслеживать статус is_maker:
is_maker = True -> применяется maker_fee_bps.
is_maker = False (исполнение по тайм-ауту) -> применяется taker_fee_bps.
Расчет на основе объема (Notional Value):
fee = trade_quantity * fill_price * (fee_bps / 10000).
Важно: комиссия рассчитывается отдельно для открытия и отдельно для закрытия позиции.
2. Метрики и аналитика
Net PnL: Итоговая прибыль после вычета всех комиссий.
Breakeven Analysis:
Рассчитать avg_fee_per_roundtrip = total_fees / total_trades.
Это значение — минимальный "грязный" профит, который должна приносить одна сделка, чтобы не торговать в убыток.
Fee Efficiency: Процент сделок, исполнившихся как Maker. Чем выше этот показатель, тем эффективнее работает execution.rs.
3. Отчетность
Выводить в консоль и сохранять в лог:
Gross PnL: $150.5 USDT
Total Fees: 45.2USDT(изнихMaker:45.2 USDT (из них Maker: 45.2USDT(изнихMaker:15.0, Taker: $30.2)
Net PnL: $105.3 USDT
Fee/Profit Ratio: 30% (показывает, какая доля прибыли "съедается" биржей).
Аргументация изменений:
Защита от "бумажной" прибыли: Установка Maker fee на уровне 0.02% (даже если Bybit предлагает 0.015% для VIP) создает необходимый запас прочности. Если стратегия прибыльна на 0.02%, она гарантированно выживет в реале.
Штраф за медлительность: Если модель выдает сигналы, которые не исполняются лимитом за отведенное время (limit_timeout_ms), стратегия будет платить 5.5 bps (Taker), что быстро выявит неэффективные точки входа.
Понятный порог: Метрика avg_fee_per_roundtrip дает кодеру четкую цель — средний тейк-профит модели должен быть существенно выше этого значения.
Критическое требование: Убедиться, что при расчете net_pnl комиссии вычитаются корректно: gross_pnl - total_fees, где gross_pnl — это разница цен покупки и продажи без учета сборов.
