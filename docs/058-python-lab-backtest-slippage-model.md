Задача 058-python-lab-backtest-slippage-model.md
Цель: Реализовать гибридную модель исполнения "Limit-then-Market" (Limit с переходом в Market по тайм-ауту), учитывающую сетевые задержки, время жизни ордера и глубину стакана (Book Walking).

Инструкции для реализации:
1. Изменения в ./python_lab/scripts/backtest.py
Новые параметры CLI:
--latency_ms: Сетевая задержка (время от сигнала до появления ордера в биржевом стакане).
--limit_timeout_ms: Время ожидания исполнения лимитного ордера (например, 5000ms).
--slippage_bps: Проскальзывание для рыночного ордера (Market-on-Timeout).
Логика симуляции "Limit-then-Market":
Сигнал (T): Модель выдает сигнал в момент времени TTT.
Задержка (T + Latency): Лимитный ордер выставляется в момент Tentry=T+latencyT_{entry} = T + \text{latency}Tentry​=T+latency. Цена лимита — Best Bid (для Buy) или Best Ask (для Sell) в момент TentryT_{entry}Tentry​.
Окно ожидания (TentryT_{entry}Tentry​ -> TtimeoutT_{timeout}Ttimeout​): Проверка по Parquet-данным: пересекала ли цена за этот период наш лимит?
Buy: if df[T_entry:T_timeout].min_price <= limit_price -> FILLED.
Sell: if df[T_entry:T_timeout].max_price >= limit_price -> FILLED.
Market-on-Timeout (TtimeoutT_{timeout}Ttimeout​): Если лимит не исполнен, выполняется рыночный ордер по цене первого доступного события после TtimeoutT_{timeout}Ttimeout​.
2. Реализация "Book Walking" (Проход по стакану)
Если объем нашего ордера больше, чем объем на 1-м уровне (ask_v_1 или bid_v_1), цена исполнения должна рассчитываться как средневзвешенная по нескольким уровням стакана.
Это касается как рыночных ордеров, так и частичного исполнения лимиток (если это поддерживается данными).
3. Техническая реализация (Polars Efficiency)
Использовать Polars метод searchsorted или filter по диапазонам времени для быстрого поиска событий внутри окна жизни ордера. Избегать циклов for по строкам датафрейма.
4. Метрики качества исполнения
В отчет добавить:
Limit Fill Rate: % ордеров, исполнившихся как лимитные (Maker).
Market Fallback Rate: % ордеров, закрытых по тайм-ауту (Taker).
Execution Latency Impact: Разница в PnL при задержке 20ms vs 100ms.
Аргументация изменений:
Реализм: Модель "Limit-then-Market" — это стандарт профессионального скальпинга. Она позволяет экономить на комиссиях (Maker rebate), но требует учета риска "ухода цены".
Защита от сверхоптимизма: Бэктест, который просто исполняет всё "по лимиту", всегда показывает сверхприбыль. Обязательный Market-on-Timeout заставит модель учить только те сигналы, которые развиваются достаточно быстро или имеют глубокий откат.
Consistency (Консистентность): Эта логика в будущем будет зеркально перенесена в ./src/trading/execution.rs (задача 069).
Критическое требование: Убедиться, что при расчете PnL используются разные комиссии для Maker (лимит) и Taker (маркет) сделок, согласно тарифам Bybit из ./exchange.toml.
