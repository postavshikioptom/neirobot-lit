
# Задача 210: Адаптивные пороги отмены (Adaptive Cancel Thresholds)

## 1. Цель задачи
Реализовать механизм динамического сужения порогов отмены ордеров (`max_distance_bps`) при росте волатильности и расширении спреда. Это позволит боту быстрее «сбрасывать» ордера в опасные моменты, минимизируя риск исполнения против сильного движения (Toxic Flow).

## 2. Инструкции для Gemini по реализации

### А. Изменения в Rust-ядре (High-Performance Math)

1.  **Зависимости ([./Cargo.toml](./Cargo.toml))**:
    *   Добавить `circular-buffer = "0.1"` для реализации сверхбыстрого кольцевого буфера без лишних аллокаций.

2.  **Эффективный расчет волатильности ([./src/data/orderbook.rs](./src/data/orderbook.rs))**:
    *   Использовать кольцевой буфер фиксированного размера (например, 100–1000 последних `mid_price`).
    *   Реализовать **алгоритм Велфорда (Welford's online variance)** для инкрементального расчета среднего и дисперсии за **O(1)**.
    *   **ВАЖНО**: При вытеснении старой цены из буфера корректно обновлять состояние (использовать инверсный метод Велфорда для скользящего окна).

3.  **Инверсная формула порога ([./src/trading/execution.rs](./src/trading/execution.rs))**:
    *   **ОШИБКА ИСПРАВЛЕНА**: Порог должен **уменьшаться** (сужаться), когда риск растет.
    *   **Формула**: `adaptive_threshold = base_threshold / (1.0 + (volatility * vol_multiplier) + (spread * spread_multiplier))`.
    *   Обеспечить жесткие границы через `clamp(min_threshold_bps, max_threshold_bps)`.

4.  **Тестирование ([./tests/orderbook_integration.rs](./tests/orderbook_integration.rs))**:
    *   Написать unit-тесты, подающие серию цен (синусоида, резкий скачок) и проверяющие корректность вычисления `volatility_bps`.

### Б. Изменения в Python Lab (Analytics)

1.  **Скрипт оптимизации**:
    *   Путь: **[./python_lab/scripts/threshold_optimizer.py](./python_lab/scripts/threshold_optimizer.py)**.
    *   **Функционал**: Поиск коэффициентов `vol_multiplier` и `spread_multiplier`, при которых количество отмен (Cancellations) коррелирует с защитой от убыточных сделок, но не блокирует нормальную торговлю.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о формуле**: Grok абсолютно прав. Моя первоначальная формула с плюсом увеличивала «терпимость» бота к уходу цены при волатильности, что в HFT смерти подобно. Использование инверсной зависимости (деление или вычитание) гарантирует, что при «шторме» бот будет держать ордера максимально близко к цене или мгновенно их снимать.
*   **Спор о Welford**: Реализация через накопление суммы и суммы квадратов в скользящем окне — стандарт для систем с низкой задержкой. Это избавляет нас от пересчета всего вектора цен на каждом тике.
*   **Спор о тестах**: Интеграция `circular-buffer` и обязательные тесты в `tests/` необходимы для верификации математики до запуска на реальные деньги.

## 4. Ожидаемый результат
Бот автоматически становится «осторожным» во время резких импульсов и «спокойным» во время флэта. Это снижает нагрузку на API (меньше отмен в тишине) и защищает капитал (быстрые отмены в буре).
