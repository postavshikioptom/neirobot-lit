# План реализации Adaptive LR (Loss-based)

##  Концепция
Вместо внешних метрик (волатильность) мы будем использовать **динамику самого обучения**. Если Loss падает стабильно — мы можем чуть ускорить шаг. Если Loss начинает колебаться или расти — замедляемся. Это работает на всех эпохах одинаково.

## Подзадача 313.1. Изменения в коде (Python Lab) - ЗАВРЕШЕНО

### [./python_lab/src/train.py](./python_lab/src/train.py)
Нужно изменить логику инициализации планировщика и цикла обучения:

1.  **Удалить**: Любые упоминания `Z-Score` или дополнительных слоев нормализации в `data_loader.py` или `model.py`. Оставляем только существующий `RobustScaler`.
2.  **Заменить**: Вместо стандартного `StepLR` или предложенного ранее `Volatility-based LR`, внедряем `ReduceLROnPlateau` или кастомный `LossAwareScheduler`.

**Конкретные правки в `train.py`**:
- **Инициализация**:
  ```python
  optimizer = torch.optim.AdamW(model.parameters(), lr=initial_lr, weight_decay=0.01)
  # Используем стандартный, но эффективный инструмент, реагирующий на Loss
  scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
      optimizer, 
      mode='min', 
      factor=0.5, 
      patience=2, 
      verbose=True
  )
  ```
- **Цикл обучения (Train Loop)**:
  После каждой эпохи (или валидации) передаем `val_loss` в планировщик:
  ```python
  scheduler.step(metrics['val_loss'])
  ```

1.  **Никакого Z-Score**: В `Dataset` и `Dataloader` используется только `RobustScaler`.
2.  **Никакой волатильности**: Мы не считаем STD цены или другие рыночные метрики для коррекции LR.
3.  **Никаких Warmup/Early Decay**: Механизм работает на основе реального Loss на протяжении всего процесса обучения.
