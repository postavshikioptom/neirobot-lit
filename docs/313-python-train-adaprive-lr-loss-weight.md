# План реализации Adaptive LR (Loss-based)

##  Концепция
Вместо внешних метрик (волатильность) мы будем использовать **динамику самого обучения**. Если Loss падает стабильно — мы можем чуть ускорить шаг. Если Loss начинает колебаться или расти — замедляемся. Это работает на всех эпохах одинаково.

### Подзадача 313.4: Расширенное логирование и аналитика по классам (LOB-Specific Metrics)

**Цель**: Получить полную прозрачность процесса обучения, чтобы понимать, "зарабатывает" ли модель на движениях или просто угадывает доминирующий класс Flat.

** - Детализация по классам (Class-wise Breakdown)**
Для каждого класса (**0: Down**, **1: Flat**, **2: Up**) в конце каждой эпохи (на Validation сете) необходимо рассчитывать и логировать:
- **Prediction Distribution**: Сколько раз модель предсказала каждый класс (в % от общего числа). Это сразу покажет, нет ли "схлопывания" в Flat.
- **Class Accuracy (Hit Rate)**: Процент верных попаданий для каждого класса отдельно. 
  - *Пример*: Из 100 предсказанных "Up" — сколько реально были "Up".
- **Confusion Matrix Details**: 
  - % случаев, когда "Up/Down" был предсказан как "Flat" (пропущенные возможности).
  - % случаев, когда "Flat" был предсказан как "Up/Down" (**Ложные входы** — самое опасное для скальпера).

** - Специфические метрики для LOB/Scalping**
Добавить расчет следующих параметров, которые критичны для Orderbook-моделей:

- **Theoretical Edge (Теоретическое преимущество)**:
  - Рассчитывается как среднее изменение цены (в тиках или %) через $k$ шагов после того, как модель дала сигнал "Up" или "Down". Если среднее движение положительное для Up и отрицательное для Down — модель имеет "Edge".
- **Signal Confidence Analysis**:
  - Средняя уверенность (Softmax probability) для **верных** предсказаний vs **неверных**. Если уверенность одинаковая — модель не понимает свои ошибки.
- **Directional Accuracy (DA)**:
  - Точность модели, если исключить все случаи предсказания Flat. Нам важно, как часто она права, когда "решается" зайти в позицию.
- **LOB Imbalance Alignment**:
  - Корреляция между предсказанием модели и текущим дисбалансом стакана (Imbalance). Помогает понять, выучила ли модель базу (стакан) или нашла свои скрытые закономерности.

** - Техническая реализация (без слома кода)**
- **Место изменений**: В `python_lab/src/train.py` в функции `validate()` или `evaluate()`.
- **Инструменты**: Использовать `sklearn.metrics.confusion_matrix` и простые операции с тензорами PyTorch/Numpy.
- **Логирование**: Вывод в консоль в виде таблицы и отправка в `WandB` (если подключен) в виде гистограмм распределения классов.
