Задача 067: Реализация Rate Limiter для REST API
Цель: Разработать надежный асинхронный механизм контроля частоты запросов, гарантирующий соблюдение квот Bybit и предотвращающий временные блокировки API-ключей.

Инструкции для реализации:
1. Добавление зависимостей (Cargo.toml)
governor = "0.6" — основная библиотека для GCRA лимитера.
nonzero_ext = "0.3" — для удобной работы с типами NonZeroU32.
2. Создание ./src/utils/rate_limiter.rs
Структура RateLimiter:
Поле limiter: governor::DefaultDirectRateLimiter.
Метод new(rate_per_sec: u32): Создает квоту и возвращает инстанс лимитера.
Метод wait(&self): async fn вызывающий self.limiter.until_ready().await.
Использование Arc: Обернуть лимитеры в Arc, так как rest_client может использоваться в многопоточной среде (например, периодическая синхронизация позиции в фоне).
3. Интеграция в ./src/trading/rest_client.rs
Поля в BybitRestClient:
orders_limiter: Arc<RateLimiter> — для order/create, order/cancel. (Лимит: ~20/s)
general_limiter: Arc<RateLimiter> — для balance, position/list, market/time. (Лимит: ~50/s)
Логика вызова:
В обертках get и post:
Определять тип запроса по path.
Вызывать self.orders_limiter.wait().await для торговых путей.
Вызывать self.general_limiter.wait().await для информационных путей.
Обработка ошибки 429:
В методе handle_response: если пришел HTTP 429, принудительно остановить текущую задачу на 5-10 секунд (tokio::time::sleep), даже если лимитер считает, что все в порядке.
4. Конфигурация из ./exchange.toml
Считать значения: [bybit.rate_limits] order_rate = 20, private_rate = 50.
Если значения не указаны — использовать безопасный fallback: 10 запросов в секунду.
Аргументация изменений:
Категории лимитов: Bybit разделяет квоты. Использование одного общего лимита на 10 запросов замедлит торговлю, а один лимит на 50 запросов может привести к блокировке при активной отмене ордеров. Разделение — самый эффективный путь.
GCRA (через governor): В отличие от простых Token Bucket, этот алгоритм лучше обрабатывает "всплески" (bursts) запросов, позволяя отправить 3-4 ордера почти одновременно, если до этого была пауза.
Arc: Позволяет безопасно передавать ссылки на лимитеры между PositionManager (фоновая синхронизация) и Execution (основной цикл).
Критическое требование: Убедиться, что wait().await вызывается до формирования подписи запроса (задача 061), так как задержка в лимитере может сделать timestamp в подписи невалидным, если он был сгенерирован заранее.
