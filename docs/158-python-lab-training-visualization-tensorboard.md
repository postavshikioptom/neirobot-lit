# Задача №158: Интеграция TensorBoard для глубокого анализа обучения

Согласно [./docs/000-architecture.md](./docs/000-architecture.md), нам нужен детальный контроль над обучением Трансформера. Мы внедрим **TensorBoard** с упором на производительность и визуализацию микроструктуры стакана (LOB).

## План реализации для Gemini AI Coder:

### 1. Настройка Layout и Custom Scalars в [./python_lab/scripts/train.py](./python_lab/scripts/train.py)
Не просто записывать всё подряд, а структурировать дашборд:
- **Custom Layout**: Использовать `writer.add_custom_scalars` для группировки графиков.
    - Вкладка **"Losses"**: совмещенные графики `train/val_loss`.
    - Вкладка **"Performance"**: `MCC`, `Precision`, `Recall`.
- **HParams**: Вызывать `writer.add_hparams` в начале запуска с базовыми параметрами, обновляя итоговые метрики в конце сессии.

### 2. Оптимизированный мониторинг весов и активаций
Чтобы не замедлять обучение (особенно при больших `seq_len`):
- **Статистика вместо гистограмм**: Для активаций слоев **Patching** и **Attention** записывать только `mean`, `std` и `max` через `forward hooks`. Полноразмерные гистограммы писать редко (параметр `--tb_hist_freq`, по умолчанию каждые 10 эпох).
- **Градиенты**: Записывать норму градиентов для каждого именованного параметра, чтобы вовремя заметить затухание (Vanishing Gradients) в глубоких слоях энкодера.

### 3. Визуализация метрик и классификации в [./python_lab/src/utils.py](./python_lab/src/utils.py)
- **Confusion Matrix**: Использовать `writer.add_figure` вместо `add_image`. Отрисовывать матрицу через `matplotlib` для сохранения интерактивности и зума в интерфейсе TensorBoard.
- **PR-Кривые**: Не использовать устаревший `add_pr_curve`. Реализовать расчет через `sklearn.metrics.precision_recall_curve` и отправлять готовый график через `add_figure`.

### 4. TensorBoard Projector (Embeddings)
Добавить визуализацию внутреннего представления данных:
- **Patching Projection**: Использовать `writer.add_embedding` для векторов после слоя патчинга. Это позволит увидеть, как модель кластеризует различные состояния стакана (например, группируются ли "агрессивные покупки" отдельно от "тихого флэта").

### 5. Логирование и CLI
- Добавить флаг `--tb_dir` (по умолчанию `runs/SYMBOL/`).
- Реализовать автоматическую очистку старых логов или версионирование, чтобы не переполнять диск при тысячах запусков Optuna.

## Аргументация (Спор с Grok):
- **Согласен**: Полные гистограммы активаций на каждой эпохе — это "убийца производительности" для Трансформеров. Переход на `mean/std/max` через хуки — верное решение.
- **Согласен**: `add_figure` для Confusion Matrix и PR-кривых гораздо гибче и современнее, чем `add_image` или устаревшие методы.
- **Согласен**: Добавление **Projector** — это киллер-фича. Для LOB-данных критически важно понимать, выучила ли модель структуру уровней стакана или просто запомнила шум.
- **Важное уточнение**: При использовании `add_embedding` нужно ограничить количество сэмплов (например, до 1000), иначе TensorBoard будет зависать при загрузке тяжелых проекций.

> [!IMPORTANT]
> **Hotfix (Задача 303-7)**:
> При вызове `log_embeddings` возникла ошибка `AttributeError: 'LiTModel' object has no attribute 'device'`.
> **Причина**: В функцию `log_embeddings` передавалась сырая модель `LiTModel` (nn.Module), которая не имеет атрибута `.device`.
> **Решение**: Использовать `next(model.parameters()).device` внутри `log_embeddings` или передавать устройство явно.
