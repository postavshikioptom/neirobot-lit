# Задача 201: Анализ реального проскальзывания против ожидаемого (Real vs Expected Slippage)

## 1. Цель задачи
Реализовать систему точного замера и анализа проскальзывания (slippage) между ценой сигнала нейросети и фактической ценой исполнения на бирже. Данные необходимы для синхронизации бэктеста ([./docs/058-python-lab-backtest-slippage-model.md](./docs/058-python-lab-backtest-slippage-model.md)) с реальностью.

## 2. Инструкции для Gemini по реализации

### А. Изменения в Rust-ядре (Performance & Logging)

1.  **Зависимости ([./Cargo.toml](./Cargo.toml))**:
    *   Добавить `csv = "1.1"` для высокопроизводительной записи логов.
    *   Убедиться в наличии `serde` с флагом `derive`.

2.  **Монотонные замеры ([./src/ml/types.rs](./src/ml/types.rs) и [./src/trading/order_manager.rs](./src/trading/order_manager.rs))**:
    *   **НЕ использовать** `chrono::Utc::now()` для вычисления дельты задержки (избегаем NTP drift).
    *   В структуру `Signal` добавить поле `start_instant: std::time::Instant`.
    *   При генерации сигнала: `let start_instant = Instant::now();`.
    *   В `OrderManager` при получении события `Fill`:
        ```rust
        let latency_ms = signal.start_instant.elapsed().as_millis() as u64;
        ```

3.  **Логирование сделок ([./src/utils/logger.rs](./src/utils/logger.rs))**:
    *   Расширить `trades.csv` в `bots/SYMBOL/logs/`.
    *   **Колонки**: `timestamp_utc` (для синхронизации), `signal_price` (mid_price в момент вывода модели), `fill_price` (средневзвешенная цена исполнения), `slippage_bps` (разница в базисных пунктах), `latency_ms` (точное время "пролета" через систему).

### Б. Изменения в Python Lab (Analytics)

1.  **Расположение файла**:
    *   **НЕ создавать** в `python_lab/analysis/`.
    *   Использовать путь: **[./python_lab/scripts/slippage_analysis.py](./python_lab/scripts/slippage_analysis.py)**. Это соответствует паттерну проекта (скрипты запуска в `scripts/`, ядро в `src/`).

2.  **Функционал скрипта**:
    *   Реализовать CLI через `argparse`: `--symbol`, `--days`, `--plot`.
    *   Загрузка данных через `polars` (быстрее `pandas` для больших логов).
    *   Вывод корреляции: `Slippage vs Volatility` и `Slippage vs Spread`.

## 3. Критические аргументы и исправления (Проверка Grok)
*   **Спор по времени**: Согласен с Grok. Использование `Instant` критично, так как системное время может корректироваться службами синхронизации во время работы бота, что даст ложные "отрицательные" или гигантские задержки.
*   **Спор по структуре**: Перенос в `scripts/` правильный, так как это инструмент командной строки для исследователя, а не модуль, импортируемый в модель.
*   **Спор по зависимости**: Прямое использование `csv` crate эффективнее, чем ручная склейка строк, и гарантирует корректную обработку спецсимволов.

## 4. Ожидаемый результат для кодера
1.  Бот при каждой сделке пишет в `trades.csv` точную задержку, измеренную через `Instant`.
2.  Скрипт в `python_lab/scripts/` строит графики, показывающие, насколько наша `slippage_model` в обучении отличается от суровой реальности Bybit.
