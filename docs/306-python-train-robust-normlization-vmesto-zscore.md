# ЗАДАЧА 306-2 ПЛАН РЕАЛИЗАЦИИ

Я провел глубокий аудит кода, чтобы найти причину внезапного появления `NaN` и падения MCC в отрицательную зону. 

**Вы правы: кодер, который уверял, что «данные берутся по именам», ошибся.** В ключевых местах конвейера (Pipeline) до сих пор используется **жесткая индексация по числам (Slicing)**, которая ломается при любом изменении структуры Parquet-файла.

### 🔍 Где именно зарыта ошибка (Аудит кода)

1.  **В `dataset.py` (метод `_process_sample`):**
    Здесь до сих пор стоит `lob_flat = x_raw[:, :200]`. 
    *   Если в Parquet-файле первые две колонки — `timestamp` и `last_update`, то в модель попадает `timestamp` вместо первой цены `ask_p_0`. 
    *   **Результат:** Числа порядка $10^{12}$ мгновенно превращают веса модели в `NaN`.

2.  **В `dataset.py` (метод `_init_memory_mode`):**
    Здесь данные переводятся в `numpy` массив через `df.to_numpy()`. В этот момент **имена колонок теряются**. Весь последующий доступ идет по индексам. Если при джойне в `load_multi_symbol_data` порядок колонок изменился (например, `ofi` встал перед `bid_v_49`), то вся структура тензора превращается в кашу.

3.  **В `normalization.py` (метод `fit`):**
    Здесь расчет идет по именам `feat_`, но при `transform` для `numpy` массива (который используется в обучении) опять идет цикл по индексам `range(len(self.params))`. Если порядок колонок в массиве и в словаре `self.params` не совпадает — нормализация ломается.

Этот план полностью переводит систему на принцип «Fail-Fast» (быстрого отказа):

Загрузка: Мы будем использовать df.select([список_имен]). Если в Parquet-файле не окажется хотя бы одного столбца (например, ask_p_48), Polars выбросит ошибку сразу, не допуская обучения на битых данных.

### 🔍 Мой аудит ситуации
1.  **Дисбаланс (Imbalance) — ГРОК ПРАВ:** Когда мы используем `RobustScaler`, мы вычитаем медиану. Если медиана объема была 100, а текущий объем 100, то после нормализации `vol = 0`. В итоге `bid_v + ask_v` может легко стать `0.0`. Деление на `1e-7` дает гигантское число.
2.  **Доходности (Past Returns) — ГРОК ОШИБСЯ:** В текущем коде `dataset.py` стоит `past_ret * 100.0`. Если мы включили `RobustScaler` для доходностей, он уже привел их к масштабу `~1.0`. Умножение на `100.0` создает входной сигнал величиной в **100**. Для нейросети это «удар кувалдой», который мгновенно вызывает `NaN` в первом же слое `LayerNorm`.
3.  **Лимиты Clamp:** Грок предлагает `clamp -20.0, 20.0`. Для `float32` в глубоком трансформере (где есть возведение в степень в Softmax) это всё еще может быть многовато.
