# Задача 224: Распределение уверенности инференса (Inference Confidence Distribution)

## 1. Цель задачи
Реализовать систему мониторинга «здоровья» ML-модели. Бот должен анализировать распределение вероятностей (softmax) и энтропию предсказаний в реальном времени, сравнивая их с базовыми значениями (Baseline) для обнаружения деградации модели и автоматического переключения в защитный режим.

## 2. Инструкции для Gemini по реализации

### А. Сбор метрик в Rust (High-Performance)

1.  **Агрегация и Сэмплирование ([./src/ml/onnx.rs](./src/ml/onnx.rs))**:
    *   **НЕ писать** каждый инференс в CSV (риск IO-latency).
    *   Реализовать сэмплирование: записывать полные вероятности (`prob_up`, `prob_down`, `prob_flat`) только для каждого N-го инференса (настройка `confidence_sample_rate`).
    *   Внедрить **EMA (Exponential Moving Average)** для энтропии предсказаний: $H = -\sum p_i \log p_i$.

2.  **Детекция дрейфа в реальном времени**:
    *   При старте загружать `model_metadata.json` (задача 056), содержащий гистограмму уверенности с валидационной выборки (Baseline).
    *   Если EMA энтропии превышает порог `entropy_drift_threshold` или текущее распределение значимо отклоняется от Baseline — генерировать `Critical Alert` через `AlertManager` (задача 222).

3.  **Интеграция с Health State ([./src/trading/risk_manager.rs](./src/trading/risk_manager.rs))**:
    *   При обнаружении высокого дрейфа (высокая энтропия = модель «растеряна») принудительно переводить бота в режим `Degraded` или `Emergency` (задача 220).

### Б. Аналитика в Python Lab (Calibration & Drift)

1.  **Создать [./python_lab/scripts/model_confidence_analysis.py](./python_lab/scripts/model_confidence_analysis.py)**:
    *   **Метрики**:
        *   **ECE (Expected Calibration Error)**: Расчет ошибки калибровки (задача 122). Проверка: если модель говорит «уверенность 90%», сбывается ли прогноз в 90% случаев?
        *   **KS-Test**: Применение теста Колмогорова-Смирнова (`scipy.stats.ks_2samp`) для сравнения живого распределения уверенности с Baseline.
    *   **Визуализация**: Reliability Diagrams и сравнение гистограмм энтропии.

### В. Конфигурация ([./src/config/types.rs](./src/config/types.rs))
*   Добавить в `BotConfig`:
    ```rust
    confidence_sample_rate: u32,     // 1 из N (например, 100)
    entropy_drift_threshold: f32,   // Порог для алертов
    enable_realtime_drift_check: bool,
    ```

## 3. Критика и аргументация (По правкам Grok)
*   **Спор об IO**: Полностью согласен. Прямая запись каждого инференса (1000 Гц) на диск убьет производительность HFT-ядра. Сэмплирование или минутная агрегация бакетов — единственный путь.
*   **Спор о дрейфе**: Мониторинг энтропии в реальном времени критичен. Если рынок изменился (режим сменился), энтропия предсказаний резко вырастет. Бот должен заметить это мгновенно и снизить риск, не дожидаясь оффлайн-анализа в Python.
*   **Спор о калибровке (ECE)**: Интеграция с задачей 122 позволяет построить «диаграммы надежности». Это база для динамической настройки порогов срабатывания нейросети.

## 4. Ожидаемый результат
Бот защищен от работы на «протухшей» модели. При резком изменении рыночной структуры модель выдает высокую энтропию, что триггерит алерт в Telegram и снижает торговый объем до восстановления параметров калибровки.
