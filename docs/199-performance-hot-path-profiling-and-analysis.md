# Задача №199: Профилирование и анализ "горячего пути" исполнения (Hot Path Profiling)

[./docs/199-performance-hot-path-profiling-and-analysis.md](./docs/199-performance-hot-path-profiling-and-analysis.md)

## План реализации

1.  **Настройка инструментов профилирования (Windows)**:
    - Использовать **`samply`** в качестве основного инструмента профилирования на Windows (использует системный бэкенд **ETW**).
    - В `Cargo.toml` для профиля `release` установить `debug = 1` или `true`, чтобы сохранить отладочные символы для анализа при сохранении всех оптимизаций.

2.  **Обновление зависимостей**:
    - Добавить в `Cargo.toml` крейт `polars = { version = "0.41", features = ["parquet"] }` для эффективного чтения исторических данных.

3.  **Режим имитации нагрузки (Replay Mode)**:
    - В [./src/bin/run-bot.rs](./src/bin/run-bot.rs) добавить флаг запуска `--replay <PATH_TO_PARQUET>`.
    - Реализовать логику подачи данных из Parquet-файлов (созданных в Фазе 5) напрямую в обработчик `on_message` стакана. Это позволит нагрузить CPU на 100%, исключив сетевые задержки как ограничивающий фактор.

4.  **Анализ "бюджета задержки" (Latency Budget)**:
    - Провести замеры времени выполнения ключевых этапов (Hot Spots):
        - **Парсинг JSON** (Zero-copy из задачи 192).
        - **Обновление LOB** (Lock-free из задачи 191).
        - **Расчет фичей** (SIMD из задачи 193).
        - **Инференс** (ONNX тюнинг из задач 196-197).
    - Выявить функции, занимающие более 5-10% времени цикла, для финальной микро-оптимизации.

## Ожидаемый результат
- Сформированный **Flamegraph** работы бота под максимальной нагрузкой в среде Windows.
- Точный Latency Breakdown (разбивка задержек) по каждому модулю.
- Подтверждение отсутствия неожиданных аллокаций или блокировок на критическом пути.
- Итоговый отчет о производительности системы перед запуском в прод.
