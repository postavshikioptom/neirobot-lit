Задача 056-python-lab-export-model-metadata.md
Цель: Реализовать генерацию расширенного файла metadata.json, который служит «паспортом» модели и содержит все необходимые параметры для сборки тензоров и инференса в Rust.

Инструкции для реализации:
1. Изменения в ./python_lab/scripts/export_onnx.py
Автономный CLI: Скрипт должен поддерживать запуск как после обучения, так и отдельно, загружая веса из файла:
Аргументы: --model_path, --config_path, --output_dir.
Динамическое извлечение:
Извлекать seq_len, n_levels, in_channels и patch_size напрямую из атрибутов загруженной модели или её конфига.
Автоматически определять output_classes (например, 3 для тернарной классификации).
Воспроизводимость:
Использовать subprocess для получения текущего git_hash коммита.
Добавить версию контракта метаданных (SemVer, например, "version": "1.0.0").
2. Консолидация данных в metadata.json
Файл должен заменить собой norm.json и содержать:

{
  "metadata_version": "1.0.0",
  "git_hash": "a1b2c3d...",
  "export_timestamp": "2026-02-03T...",
  "model_params": {
    "architecture": "LiT-Transformer",
    "seq_len": 50,
    "n_levels": 50,
    "in_channels": 3,
    "feature_order": ["price", "volume", "imbalance"],
    "output_classes": 3,
    "label_map": {"0": "Up", "1": "Down", "2": "Flat"}
  },
  "normalization": {
    "method": "z-score",
    "mean": [0.001, 15.2, -0.05],
    "std": [0.0002, 3.1, 0.4]
  }
}
3. Подготовка для Rust-интеграции
В ./src/ml/types.rs (в рамках задачи 033) предусмотреть структуру ModelMetadata, которая позволит десериализовать этот файл через serde_json.
Это обеспечит "единый источник истины": Rust-ядро при старте читает только metadata.json и на его основе конфигурирует размер кольцевого буфера и параметры нормализации.
4. Валидация
Добавить в скрипт экспорта проверку на наличие критических полей и отсутствие NaN/Inf в параметрах нормализации. Если проверка не пройдена — файл не записывается, скрипт завершается с ошибкой.
Аргументация изменений:
Loose Coupling (Слабая связанность): Возможность экспорта из сохраненного чекпоинта позволяет разделять процессы обучения (на сервере с GPU) и финализации модели (на локальной машине).
Git-хеш: Без него невозможно понять, на каком именно коде была получена "лучшая" модель, что критично для исправления багов.
Динамика: Мы не ограничиваем бота 50 уровнями стакана. Если Bybit изменит глубину или мы решим использовать топ-20, Rust-ядро подстроится автоматически, прочитав метаданные.
Критическое требование: Убедиться, что порядок в feature_order в метаданных полностью совпадает с порядком каналов в тензоре, который формирует dataset.py. Любое расхождение приведет к тому, что модель будет получать "объемы" вместо "цен".
