Задача 091: Добавление признака Past Returns (Multi-scale Momentum)
Цель: Обогатить входные данные модели информацией о динамике цены на различных временных горизонтах (Multi-scale Log-Returns), позволяя трансформеру учитывать моментум.

1. Изменения в Python-лаборатории (./python/)
1.1. Конфигурация и Hyperparams
BotConfig / Optuna: Вынести список лагов в конфиг.
past_returns_lags: [10, 50, 100] (базовые, подлежат тюнингу в задаче 030).
Normalization: Для каждого лага рассчитывать индивидуальный коэффициент масштабирования (Std), так как волатильность на 10 и 100 лагах различается на порядок.
1.2. Preprocessing (dataset.py)
Логика: Расчет Rn=ln⁡(mid_pricet)−ln⁡(mid_pricet−n)R_n = \ln(mid\_price_t) - \ln(mid\_price_{t-n})Rn​=ln(mid_pricet​)−ln(mid_pricet−n​).
NaN Handling: Первые n значений заполнять 0.0 (нейтральный сигнал), чтобы избежать NaN в тензоре.
Tensor Mapping:
Каждый лаг добавляется как отдельный канал.
Broadcast: Поскольку лог-доходность — это скаляр для всего среза LOB, значение транслируется (broadcast) на все 50 уровней стакана для сохранения формы тензора (Channels, Levels, Time).
Итоговая форма: (3 + N_lags, 50, seq_len).
2. Изменения в Rust (./src/ml/tensor.rs)
History Buffer:
Реализовать mid_price_history: VecDeque<Decimal> с максимальной длиной max(lags).
В методе push_snapshot обновлять буфер.
Parity:
Расчет в Rust: (current_mid.ln() - old_mid.ln()) в f32.
Если буфер еще не заполнен до нужного лага — использовать 0.0.
Performance: Использовать SmallVec или преаллоцированный буфер для формирования каналов, минимизируя копирование.
3. Почему этот план лучше (Аргументы Grok):
Separate Channels: Выделение каждого горизонта (10, 50, 100) в отдельный канал позволяет механизму внимания (Attention) в трансформере обучаться разным весам для разного моментума.
Broadcasting: Трансляция скаляра на 50 уровней — стандартный SOTA-подход для внедрения глобальных признаков (Global Features) в пространственные структуры (LOB), обеспечивающий совместимость с CNN/ViT слоями.
Optuna Integration: Оптимальные лаги зависят от волатильности инструмента (для CAKEUSDT и BTCUSDT они будут разными). Гибкая настройка через конфиг критична для масштабирования.
Numerical Stability: Индивидуальное масштабирование каждого лага предотвращает доминирование длинных горизонтов (с большой амплитудой) над короткими.
4. Критические требования
Log-Returns: Обязательно логарифмическая форма для симметрии доходности.
Parity Check: Создать тест, который экспортирует тензор из Python и сравнивает его с тензором, собранным в Rust на тех же данных (до 6 знака).
Ablation Study: После реализации замерить MCC (задача 051). Если метрика не выросла — признак считается избыточным.
5. Тестирование
Unit test (Rust): Проверка VecDeque на переполнение и корректность выдачи лага n.
Training test: Проверка сходимости модели с новыми каналами (отсутствие Exploding Gradients).
