# Задача 217: Аудит чувствительных действий (Security Audit Log)

## 1. Цель задачи
Реализовать систему защищенного аудита критических событий. Каждый лог должен быть связан с предыдущим через криптографический хеш (HMAC), образуя неизменяемую цепочку. Это позволит гарантировать, что ни одна запись не была удалена или изменена злоумышленником.

## 2. Инструкции для Gemini по реализации

### А. Ядро аудита (Rust)

1.  **Зависимости ([./Cargo.toml](./Cargo.toml))**:
    *   `sha2 = "0.10"` и `hmac = "0.12"` (для защищенной цепочки).
    *   `chrono = "0.4"` (таймстампы).
    *   `csv = "1.3"` (структурированная запись).

2.  **Структура AuditLogger ([./src/utils/audit.rs](./src/utils/audit.rs))**:
    *   Создать структуру `AuditLogger` со следующими полями: `file: std::fs::File`, `last_hash: Vec<u8>`.
    *   **Инициализация (`init`)**:
        *   Открыть `bots/SYMBOL/logs/security_audit.csv` в режиме `Append`.
        *   Если файл не пуст, считать последнюю строку и извлечь хеш. Если пуст — использовать "генезис-хеш" (например, хеш от `master_key`).
    *   **Метод `log_event`**:
        *   Принимает `actor` (System/Startup), `action`, `status`, `old_value`, `new_value`.
        *   **Цепочка хеширования**: `current_hash = HMAC_SHA256(key: master_key, data: prev_hash + row_data)`.
        *   **Безопасность**: Установить права доступа к файлу `600` (только владелец) и выполнять `flush()` после каждой записи.

3.  **Точки интеграции**:
    *   **[./src/config/loader.rs](./src/config/loader.rs)**: Фиксация каждой попытки расшифровки конфига (успех/провал).
    *   **[./src/trading/risk_manager.rs](./src/trading/risk_manager.rs)**: Логирование срабатывания защитных гейтов (Price Deviation, Max Daily Loss).

### Б. Аналитика аудита (Python)

1.  **Создать [./python_lab/scripts/security_audit_checker.py](./python_lab/scripts/security_audit_checker.py)**:
    *   **Валидация**: Скрипт запрашивает `NEIRO_MASTER_KEY` и проверяет всю цепочку хешей в CSV. Если цепочка разорвана — вывод `CRITICAL: Log Tampering Detected`.
    *   **Детектор аномалий**:
        *   Более 3 неудачных попыток расшифровки в час.
        *   Срабатывание более 5 риск-гейтов за 10 минут.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о состоянии (Stateful)**: Полностью согласен. Функции в `logger.rs` недостаточно. Нужна структура `AuditLogger`, которая «помнит» последний хеш в рамках сессии и умеет восстанавливать его из файла при перезапуске бота.
*   **Спор об HMAC**: Использование HMAC с секретным `master_key` (из задачи 216) вместо обычного SHA-256 делает лог на порядок защищеннее. Даже имея доступ к коду, злоумышленник не сможет пересчитать хеши после удаления «неудобной» строки без знания ключа.
*   **Спор о Manual**: Поскольку в Phase 1 нет удаленного управления, `actor` будет помечен как `Startup` (изменение конфига вручную перед запуском) или `System` (автоматика). Это закладывает фундамент для будущего аудита действий оператора.

## 4. Ожидаемый результат
Файл `security_audit.csv`, где каждая строка подтверждает целостность предыдущей. Попытка удалить строку или изменить цену сделки в логе будет мгновенно обнаружена скриптом проверки.
