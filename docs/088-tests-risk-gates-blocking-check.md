Задача 088: Тестирование риск-гейтов (Blocking Logic)
Цель: Проверить надежность защитных механизмов RiskManager. Убедиться в корректности математических расчетов (BPS, отклонение) и логики блокировки при экстремальных рыночных условиях.

1. Изменения в Cargo.toml
Добавить в [dev-dependencies]:
tracing-test = "0.2" (для захвата и проверки логов warn!/critical!).
mockall = "0.13".
2. Архитектура тестов
Файл: ./tests/risk_manager_tests.rs.
Метод: Для простых гейтов (Spread, Deviation) — прямые вызовы методов. Для гейтов, зависящих от состояния (Max Position, Max Orders) — мокирование соответствующих трейтов доступа к данным.
3. Тестовые сценарии (Scenarios)
Spread BPS Filter (Задача 073):
Формула: bps = ((ask - bid) / mid) * 10000.
Assert: bid=100.0, ask=100.1 -> 10 bps. При лимите 5 bps — блокировка.
Edge Case: mid = 0 (пустой стакан) -> Должен вернуть false без паники (div by zero guard).
Drawdown & Peak Logic (Задача 072):
Peak: Вход 1000 -> 1100 (пик 1100). Просадка до 950 (DD = 150).
Reset: Вручную установить last_reset_date на вчерашнюю дату в структуре. Проверить, что check_drawdown сбрасывает is_blocked.
Max Position & Orders (Трейты):
Использовать мок трейта TradeStateProvider (или аналогичного), который возвращает current_notional и active_orders_count.
Проверить блокировку при count == limit.
Price Deviation & Tick (Задача 075):
Deviation: mid=100.0, order=101.1, limit=0.01 -> Блокировка (1.1% > 1%).
Precision: price=10.0005, tick=0.01 -> Блокировка (не кратно тику).
Config Flexibility:
Проверить, что при Option::None в конфиге гейт всегда возвращает true (пропуск).
4. Критические требования
Log Assertions: С помощью #[tracing_test::traced_test] проверять, что при блокировке в логах появляется специфическое сообщение (например, "Spread too wide").
Fail-Fast: Тест на комбинацию гейтов — если первый гейт заблокировал, остальные не должны вызываться (цепочка проверок).
No Floating Point: Все сравнения и расчеты только через Decimal.
5. Почему этот план лучше (Аргументы Grok):
Pure Logic Testing: Гейты спреда и отклонения — это чистые функции. Тестировать их без моков проще и быстрее.
Time Simulation: Вместо сложного мокирования системного времени мы просто меняем поле даты в структуре RiskManager, что делает тесты детерминированными.
Tracing-test: Позволяет убедиться, что трейдер получит визуальное уведомление о причине блокировки ордера, а не просто "молчаливый" отказ.
Zero-Division Guard: Проверка на mid=0 критична для стабильности бота при кратковременных исчезновениях ликвидности.
6. Запуск и покрытие
Команда: cargo test --test risk_manager_tests.
Ожидаемое покрытие: Все if и match ветки в методах валидации.
