# Задача 223: Тепловые карты глубины стакана (Orderbook Depth Heatmaps)

## 1. Цель задачи
Реализовать аналитический инструмент для визуализации динамики ликвидности (стен) в стакане. Система должна отображать плотность Bid/Ask уровней в координатах времени и относительной цены (BPS), позволяя соотносить действия бота с реальным состоянием рынка.

## 2. Инструкции для Gemini по реализации

### А. Аналитический модуль (Python Lab)

1.  **Создать файл `./python_lab/scripts/lob_heatmap.py`**:
    *   **Входные данные**: Parquet-файлы из `./bots/SYMBOL/data/raw/` и `./bots/SYMBOL/logs/trades.csv`.
    *   **Преобразование координат (Signed BPS)**:
        *   Центральная линия (Y=0) — это `mid_price`.
        *   **Asks**: Положительные значения BPS (`(ask_p - mid) / mid * 10000`).
        *   **Bids**: Отрицательные значения BPS (`(bid_p - mid) / mid * 10000`).
    *   **Агрегация (2D Гистограмма)**:
        *   Использовать `np.histogram2d(time_bins, price_bps_bins, weights=log1p_volume)` для эффективного сжатия миллионов строк в матрицу плотности.
        *   Параметры биннинга (размер ячейки) должны быть настраиваемыми через CLI.

2.  **Визуализация (Plotly & Matplotlib)**:
    *   **Plotly (основной)**: Генерация интерактивного HTML с возможностью Zoom/Pan (важно для HFT данных). Использовать `go.Heatmap`.
    *   **Matplotlib (fallback)**: Генерация статического PNG через `pcolormesh`.
    *   **Цветовая схема**: `Viridis` или `Inferno` (логарифмическая шкала).
    *   **Overlay**: Накладывать маркеры сделок (Buy/Sell) из `trades.csv` поверх тепловой карты.

### Б. Конфигурация и CLI
1.  **Параметры запуска**:
    *   `--symbol`: Токен для анализа.
    *   `--start`, `--end`: Временной диапазон в формате ISO (обязательно для сегментации данных).
    *   `--depth_bps`: Глубина отображения (например, 100 bps вверх и вниз).
    *   `--export_csv`: Опциональное сохранение рассчитанной матрицы плотности в CSV для внешнего анализа.

2.  **Зависимости**:
    *   Добавить `plotly`, `scipy` и `matplotlib` в `./python_lab/requirements.txt`.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о Signed BPS**: Полностью согласен с Grok. Смешивание Bid и Ask в одной положительной шкале делает невозможным анализ «сжатия» спреда и структуры стен. Разнос по знаку (Ask > 0, Bid < 0) — индустриальный стандарт.
*   **Спор об интерактивности**: В HFT данных невозможно увидеть детали на статичном PNG. Plotly позволяет «провалиться» в конкретную секунду, когда бот совершил сделку, и увидеть, не была ли стенка фейковой (spoofing).
*   **Спор об агрегации**: Прямая отрисовка всех точек стакана приведет к краху браузера. `np.histogram2d` — единственный путь к производительной визуализации гигабайт данных LOB.
