# Задача №198: Оптимизация производительности: Статическая диспетчеризация (Static Dispatch)

[./docs/198-performance-static-dispatch-optimization.md](./docs/198-performance-static-dispatch-optimization.md)

## План реализации

1.  **Рефакторинг [./src/risk/risk_manager.rs](./src/risk/risk_manager.rs)**:
    - **Замена dyn на Enum**: Выявить использование `Box<dyn RiskGate>` и заменить его на перечисление `RiskGateKind`, включающее все конкретные реализации (например, `MaxPosition`, `PriceDeviation`, `SlippageCheck` из Фазы 8).
    - **Диспетчеризация через match**: В методе `check_risk` использовать `match` по вариантам Enum. Это позволяет компилятору выполнять **devirtualization** и агрессивный **inlining** кода проверок, устраняя накладные расходы на вызовы через таблицу виртуальных методов (vtable).

2.  **Оптимизация [./src/trading/execution.rs](./src/trading/execution.rs)**:
    - **Использование Generics**: Заменить использование трейт-объектов в логике исполнения на обобщенные параметры типа с ограничениями: `T: Strategy + Send + Sync`.
    - Это обеспечит мономорфизацию кода во время компиляции, превращая вызовы методов стратегии в прямые переходы, что критично для "горячего пути" (hot path) обработки сигнала.

3.  **Атрибуты Inlining**:
    - Добавить аннотации `#[inline]` для небольших, часто вызываемых методов в [./src/data/orderbook.rs](./src/data/orderbook.rs) (например, `get_mid_price`, `is_empty`) и [./src/utils/helpers.rs](./src/utils/helpers.rs).
    - В сочетании с **LTO (Link Time Optimization)** и `codegen-units = 1` (из задачи 186), это позволит LLVM проводить сквозную оптимизацию между модулями.

4.  **Валидация**:
    - Убедиться, что архитектура остается расширяемой: добавление нового гейта требует только добавления варианта в Enum, что безопасно для текущего набора логики.
    - Проверить отсутствие `Box<dyn ...>` в критических циклах через поиск по коду.

## Ожидаемый результат
- Полное устранение косвенных вызовов (indirect calls) на этапе выполнения торговой логики.
- Уменьшение количества промахов предсказателя ветвлений (branch mispredictions) за счет замены vtable на типизированные переходы.
- Рост производительности за счет возможности инлайнинга кода риск-гейтов непосредственно в цикл принятия решения.
