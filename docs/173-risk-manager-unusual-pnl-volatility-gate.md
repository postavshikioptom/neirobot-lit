# **Задача №173: Гейт аномальной волатильности PnL (Unusual PnL Volatility Gate)**

**Цель**: Предотвращение неконтролируемого поведения стратегии или багов модели. Бот должен отслеживать волатильность собственных сделок и блокировать торговлю, если результаты становятся слишком нестабильными (высокий **Standard Deviation**) или фиксируется аномальный выброс относительно среднего (**Z-score Outlier**).

---

## **План реализации для Gemini AI Coder:**

### **1. Изменения в [./src/config/types.rs](./src/config/types.rs)**
Добавить параметры в структуру `RiskConfig` (изоляция **per-bot**):
- **`pnl_volatility_window`**: `usize` (окно последних сделок, например 20).
- **`max_pnl_std_dev_bps`**: `u32` (макс. допустимое стандартное отклонение в базисных пунктах).
- **`max_pnl_z_score_threshold`**: `f64` (порог Z-score для детекции выбросов, например 3.0–5.0).

### **2. Состояние в [./src/risk/risk_manager.rs](./src/risk/risk_manager.rs)**
Реализовать вспомогательную структуру `PnlStats` для инкрементального расчета **unbiased sample variance** за $O(1)$:
- **Поля**: `pnls: VecDeque<f64>`, `sum: f64`, `sum_sq: f64`, `n: usize`.
- **Метод `update(x: f64)`**:
    1. Если окно заполнено, вычесть старое значение: `sum -= old`, `sum_sq -= old * old`.
    2. Добавить новое: `sum += x`, `sum_sq += x * x`.
- **Метод `std_dev() -> f64`**:
    - Формула несмещенной дисперсии: `var = (sum_sq - (sum * sum / n)) / (n - 1)`.
    - Вернуть `sqrt(var)` при $n \ge 2$, иначе `0.0`.

### **3. Логика детекции аномалий (Z-score)**
Внедрить проверку выбросов в `PnlStats`:
- **Метод `is_outlier(x: f64) -> bool`**:
    - Расчитать `mean = sum / n`.
    - `z_score = (x - mean).abs() / std_dev()`.
    - Если `z_score > max_pnl_z_score_threshold`, помечать сделку как аномальную.

### **4. Интеграция и триггеры**
- **Источник данных**: Вызывать `risk_manager.update_pnl_stats(pnl_bps)` в `execution.rs` (или `run-bot.rs`) сразу после получения филла о закрытии позиции от `PositionManager` (задача [064](./docs/000-tasks_list.md)).
- **Risk Gate**: В методе `check_risk_gates` добавить проверку:
  ```rust
  if stats.n >= 2 && stats.std_dev() > config.max_pnl_std_dev_bps as f64 {
      return Err(RiskError::UnusualVolatility);
  }
  if stats.n >= 2 && stats.is_outlier(last_pnl) {
      return Err(RiskError::PnlOutlierDetected);
  }
  ```
- **Действие**: `emergency_market_close` и остановка бота.

### **5. Тестирование в [./tests/risk_gates.rs](./tests/risk_gates.rs)**
- **Тест на волатильность**: Подать серию PnL в bps: `[10, -50, 40]`. При `mean=0`, `sample_var = (100 + 2500 + 1600) / 2 = 2100`. `std = 45.8`. Убедиться, что при лимите 30 bps гейт закрывается.
- **Тест на выброс**: При `mean=10` и `std=5` подать сделку `-40`. `Z-score = |-40 - 10| / 5 = 10.0`. При пороге 3.0 бот должен остановиться.

## **Аргументация (согласовано с Grok):**
1. **Unbiased Variance**: Использование `n-1` в знаменателе критично для малых окон (n=20), так как обычная дисперсия занижает реальный риск.
2. **Z-score vs Fixed Mean**: Отказ от сравнения с "простым средним" в пользу Z-score позволяет динамически адаптироваться к доходности стратегии. Если бот начал зарабатывать больше, Z-score не будет считать это выбросом, если волатильность тоже выросла пропорционально.
3. **Performance $O(1)$**: Метод суммы квадратов позволяет избежать циклов при каждой сделке, сохраняя микросекундную задержку в `RiskManager`.
4. **Division by Zero**: Добавлены явные проверки `n < 2` и `std == 0` для предотвращения паники (panic) Rust-кода.
