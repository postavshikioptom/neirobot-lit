
# Задача 211: Рефакторинг бэктест-движка в Event-Driven (Event-Driven Backtest Refactor)

## 1. Цель задачи
Перевести бэктестер в `./python_lab/` на событийно-ориентированную архитектуру. Это необходимо для точной симуляции задержек, очередности исполнения ордеров и работы логики `BotConfig` в условиях, максимально приближенных к живому рынку.

## 2. Инструкции для Gemini по реализации

### А. Ядро бэктестера (Event Loop)
1.  **Создать файл `./python_lab/src/backtest/engine.py`**:
    *   Реализовать очередь событий на базе `heapq`.
    *   **Базовая логика цикла**:
        ```python
        import heapq
        # events: List[Tuple[int, Event]] - куча, сортированная по timestamp (ms/us)
        while events:
            ts, event = heapq.heappop(events)
            # Обработка: MarketUpdate -> Signal -> Order -> Fill
            self.process_event(event)
        ```
2.  **Оптимизация (Numba)**:
    *   Для обеспечения скорости обработки миллионов событий использовать `@numba.jit` на критических участках (матчинг ордеров, расчет PnL).

### Б. Моделирование и Конфигурация
1.  **Интеграция настроек**:
    *   Использовать структуру из `./src/config/types.rs` (`BotConfig`). В Python это должен быть словарь или DataClass, полностью повторяющий параметры `sor`, `chasing` и `iceberg`.
2.  **Симуляция Matching Engine**:
    *   Реализовать логику исполнения лимитных ордеров на основе данных из задачи 203: ордер исполняется только при пересечении цены или накоплении достаточного объема сделок «перед нами».
3.  **Инъекция задержек**:
    *   Добавлять фиксированные или распределенные задержки (`internal_latency`, `network_latency`) между `SignalEvent` и `OrderEvent`.

### В. Интеграция и Валидация
1.  **Точка входа**:
    *   Обновить существующий скрипт `./python_lab/backtest.py`. Теперь он должен инициализировать `EventEngine`, загружать Parquet-данные в виде последовательности `MarketEvent` и запускать цикл.
2.  **Тестирование**:
    *   Создать базовые тесты в `./python_lab/tests/test_engine.py` для проверки корректности исполнения (например, проверка, что ордер не исполняется, если цена не дошла до него).

## 3. Ожидаемый результат
Бэктестер перестает быть «табличным» и начинает учитывать фактор времени. Результаты бэктеста должны включать в себя метрики проскальзывания и процента неисполненных ордеров, что позволит калибровать параметры `BotConfig` перед деплоем в Rust.
