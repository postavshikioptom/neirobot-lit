# Задача 226: Скрипт запуска и управления фермой ботов (Multi-instance Runner)

## 1. Цель задачи
Реализовать систему оркестрации на Python для управления «фермой» из десятков и сотен ботов. Система должна обеспечивать параллельный запуск, динамическое распределение ресурсов (ядра CPU, порты) и интеграцию с `systemd` для обеспечения отказоустойчивости всей инфраструктуры.

## 2. Инструкции для Gemini по реализации

### А. Оркестратор ([./scripts/farm_manager.py](./scripts/farm_manager.py))

1.  **Конфигурация фермы ([./farm.toml](./farm.toml))**:
    *   **НЕ использовать** `global.toml` для настроек фермы. Создать отдельный файл для списка символов, базового порта и лимитов ресурсов.

2.  **Запуск и управление (Parallel & Isolated)**:
    *   **Параллелизм**: Использовать `concurrent.futures.ThreadPoolExecutor` для ускоренного запуска группы ботов.
    *   **CPU Affinity**: Для каждого процесса вычислять маску ядер и запускать через `taskset -c N` (или `psutil.Process().cpu_affinity()`), изолируя ботов друг от друга.
    *   **Порты**: Назначать порты мониторинга динамически и передавать их через аргумент командной строки `--monitoring-port NNNN` (задача 221).
    *   **Лимиты**: Настраивать лимиты памяти через `cgroups` или генерацию `systemd` параметров `MemoryMax`.

3.  **Жизненный цикл (Graceful Shutdown)**:
    *   При остановке фермы скрипт должен корректно пробрасывать `SIGTERM` всем дочерним процессам и дожидаться их завершения.

### Б. Мониторинг и Инфраструктура

1.  **Dashboard ([./python_lab/scripts/farm_dashboard.py](./python_lab/scripts/farm_dashboard.py))**:
    *   Использовать библиотеки `rich` и `psutil` для вывода таблицы состояния: **Symbol | PID | CPU Core | RAM | Uptime | Status**.

2.  **Интеграция с Systemd**:
    *   Реализовать генерацию юнитов на основе [./infra/neirobot@.service](./infra/neirobot@.service) для каждого символа из списка фермы.

3.  **Глобальные Алерты**:
    *   Интегрировать проверку: если > 10% ботов фермы находятся в состоянии `Dead`, отправлять `Critical` уведомление в Telegram (задача 222).

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о конфигах**: Согласен с Grok. Rust-конфиг (`global.toml`) должен оставаться чистым от параметров оркестрации. Python-менеджер — это внешняя надстройка, у которой должен быть свой `farm.toml`.
*   **Спор о портах**: Динамическая передача через CLI (`--monitoring-port`) — единственно верный путь. Попытка перезаписывать `BotConfig` перед каждым стартом приведет к гонкам данных (Race Condition) при массовом запуске.
*   **Спор о CPU Affinity**: В HFT это критично. Если два активных бота начнут «драться» за одно ядро CPU, задержки инференса (Inference Latency) вырастут в разы. Изоляция ядер через `taskset` — база производительности.

## 4. Ожидаемый результат
Управление сотней ботов сводится к одной команде `python farm_manager.py start --all`. Система сама распределит их по ядрам, назначит порты и создаст защитные cgroups-лимиты, гарантируя стабильность всей фермы.

**Gemini, при реализации в `farm_manager.py`: используй `psutil` для кроссплатформенного мониторинга ресурсов и управления приоритетами процессов (Process Priority).**
