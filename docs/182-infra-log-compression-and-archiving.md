# **Задача №182: Сжатие и архивация логов (Log Compression and Archiving)**

**Цель**: Обеспечение стабильной работы бота в режиме 24/7 без риска переполнения диска. В HFT-системах объем логов растет экспоненциально, поэтому необходимо реализовать автоматическую ротацию через `tracing-appender` и фоновое сжатие старых файлов с помощью **Zstd** для минимизации нагрузки на CPU и диск.

---


### **2. Настройка логирования в [./src/utils/logger.rs](./src/utils/logger.rs)**
Обновить конфигурацию `tracing` (задача [008](./docs/000-tasks_list.md)):
- **Rotation**: Использовать `tracing_appender::rolling::daily` или `hourly` для автоматической ротации сырых текстовых (JSON) логов.
- **Async**: Убедиться в использовании `non_blocking` записи, чтобы архивация или медленный диск не блокировали основной поток инференса.

### **3. Логика архивации в [./src/risk/health_monitor.rs](./src/risk/health_monitor.rs)**
Реализовать периодическую задачу (раз в час) для обработки ротированных логов:
- **Compression (Zstd)**: 
    - Найти файлы в папке `logs/`, которые не имеют расширения `.zst` и не являются текущим активным логом.
    - Использовать `tokio::spawn_blocking`, чтобы вынести `zstd::encode_all` из основного асинхронного рантайма.
    - Уровень сжатия: `1` (минимальная нагрузка на CPU при хорошем коэффициенте сжатия).
- **Retention (Cleanup)**: 
    - Удалять сжатые файлы (`.zst`), дата создания которых старше `config.log_retention_days`.

## **Аргументы и обоснование (спор с Grok):**
1. **Manual Compression**: Поскольку `tracing-appender` не поддерживает нативное сжатие, реализация через `HealthMonitor` является самым чистым архитектурным решением. Это позволяет избежать блокировки записи логов во время тяжелых операций сжатия.
2. **Почему Zstd?**: В отличие от Gzip, Zstd значительно быстрее на декомпрессии и сжатии при тех же коэффициентах, что критично для серверов с высокой плотностью запущенных ботов.
3. **Spawn Blocking**: Операции с ФС и сжатием являются синхронными. Их выполнение внутри `spawn_blocking` предотвращает "замирание" (stalling) асинхронного экзекутора бота.
4. **Structured JSON**: Логи ротируются в JSON формате, что позволяет после декомпрессии легко анализировать их через `grep`, `jq` или импортировать в ELK/ClickHouse.
