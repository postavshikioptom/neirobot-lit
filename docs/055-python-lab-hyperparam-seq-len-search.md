Задача 055-python-lab-hyperparam-seq-len-search.md
Цель: Реализовать автоматизированный поиск оптимальной глубины истории стакана (seq_len) с использованием Polars для подготовки окон и Optuna для минимизации потерь.

Инструкции для Gemini:
1. Изменения в ./python_lab/src/dataset.py
Эффективные окна (Polars-native):
Вместо копирования данных в numpy, используйте Polars оконные функции (rolling/grouping) для формирования последовательностей.
Для подготовки torch.Tensor используйте метод to_numpy() только на финальном этапе формирования батча, чтобы минимизировать аллокации.
Важно: Реализовать корректную обработку границ — первая последовательность в датасете может начаться только после накопления первых seq_len строк.
2. Изменения в ./python_lab/src/lit_model.py
Positional Encoding & Masking:
Реализовать позиционное кодирование, которое поддерживает срез до текущей seq_len: self.pe = self.pe[:, :seq_len, :].
Если в обучении используются последовательности разной длины (например, в рамках одного эксперимента), добавить поддержку src_key_padding_mask в Transformer Encoder.
3. Изменения в ./python_lab/scripts/train.py
Optuna Objective:
Параметр: seq_len = trial.suggest_int("seq_len", 10, 100, step=10).
Early Stopping: Интегрировать EarlyStopping в каждый trial, чтобы прерывать обучение на неэффективных длинах последовательностей.
Критерий: Минимизировать val_loss (или максимизировать MCC).
Сохранение результата: Выбранное best_seq_len должно быть сохранено в глобальный конфиг эксперимента.
4. Экспорт и Rust-интеграция
Metadata: Скрипт экспорта должен записывать seq_len в файл metadata.json (в папке модели бота).
Rust (ML/Tensor): В ./src/ml/tensor.rs добавить логику чтения seq_len из метаданных для инициализации циклического буфера (Ring Buffer) соответствующего размера.
Аргументация изменений:
Polars Efficiency: В крипто-LOB данных могут быть миллионы строк. Polars позволяет делать rolling-операции на порядки быстрее, чем циклы в Python или манипуляции с индексами в numpy.
Latency vs Accuracy: В Rust-ядре задержка инференса напрямую зависит от seq_len. Фиксация оптимального значения в metadata.json позволяет билдеру тензоров подготовить память заранее, избегая аллокаций в горячем цикле.
Transformer Masking: Даже если мы фиксируем seq_len для конкретной модели, поддержка маскирования делает код более надежным при обработке "холодного старта" бота (когда данных еще меньше, чем seq_len).
Критическое требование: Убедиться, что при смене seq_len в Optuna корректно пересчитываются индексы таргетов (Labels), чтобы модель всегда предсказывала будущее относительно последнего снапшота в окне.
