# Задача 212: Симуляция очереди лимитных ордеров (Limit Order Queue Simulation)

## 1. Цель задачи
Реализовать в бэктестере логику «очереди» (FIFO) для лимитных ордеров. Это критично для устранения завышенных результатов (Selection Bias): ордер должен считаться исполненным только после того, как через уровень пройдет достаточный объем сделок других участников.

## 2. Инструкции для Gemini по реализации

### А. Логика очереди (Matching Logic)
1.  **Создать файл `./python_lab/src/backtest/matching.py`**:
    *   Реализовать класс `QueueTracker`.
    *   **Метод `place_order(price, volume_at_level)`**:
        *   Принимает цену и текущий объем стакана из Parquet (схема 012).
        *   Устанавливает `v_ahead` на основе `queue_model`.
    *   **Метод `update(trade_price, trade_volume)`**:
        *   Вызывается при получении события `MarketTrade`.
        *   Если `trade_price == order_price`, уменьшать `v_ahead` на `trade_volume`.
        *   Ордер готов к исполнению (`is_filled`), когда `v_ahead <= 0`.
2.  **Оптимизация (Numba)**:
    *   Использовать `@numba.njit` для метода `update`, так как он будет вызываться миллионы раз в цикле бэктеста.

### Б. Конфигурация и Данные
1.  **Конфигурация бэктеста**:
    *   **НЕ менять** `src/config/types.rs` в Rust.
    *   Добавить параметры в Python-скрипт `./python_lab/backtest.py` (через argparse или отдельный словарь настроек):
        *   `queue_model`: `conservative` (весь объем уровня перед нами) или `probabilistic` (случайная позиция 50-100%).
2.  **Загрузка данных (Polars)**:
    *   Обеспечить загрузку колонок сделок и дельт стакана из Parquet файлов в `./bots/SYMBOL/data/raw/`.

### В. Интеграция и Тестирование
1.  **Обновление Engine**:
    *   Интегрировать `QueueTracker` в `EventEngine` (из задачи 211). При получении `MarketTradeEvent` обновлять состояние всех активных лимитных ордеров.
2.  **Тесты**:
    *   Создать `./python_lab/tests/test_matching.py`.
    *   **Кейсы**: частичное исполнение уровня (ордер не заполнен), полное проедание уровня (ордер заполнен), отмена ордера (удаление из трекера).

## 3. Ожидаемый результат
Бэктестер выдает более консервативные и реалистичные результаты. Мы сможем увидеть «зависание» ордеров в стакане, что заставит нас оптимизировать логику Chasing (задача 208) для минимизации потерь при уходе цены.
