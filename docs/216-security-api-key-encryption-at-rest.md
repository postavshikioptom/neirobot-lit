# Задача 216: Шифрование API-ключей при хранении (API Key Encryption at Rest)

## 1. Цель задачи
Реализовать механизм защиты конфиденциальных данных (API-ключей и секретов) с использованием аутентифицированного шифрования. Ключи на диске должны храниться в зашифрованном виде (префикс `ENC:`), расшифровываясь только в памяти бота при запуске с использованием мастер-пароля.

## 2. Инструкции для Gemini по реализации

### А. Изменения в Rust-ядре (Security & Crypto)

1.  **Зависимости (./Cargo.toml)**:
    *   `aes-gcm = "0.10"` (AES-256-GCM для шифрования).
    *   `argon2 = "0.5"` (Для деривации ключа из пароля).
    *   `zeroize = { version = "1.8", features = ["derive"] }` (Для безопасной очистки памяти).
    *   `base64 = "0.22"` (Для кодирования бинарных данных).

2.  **Ядро криптографии (./src/utils/crypto.rs)**:
    *   **Деривация ключа**: Использовать **Argon2id** (параметры: `m=19456, t=2, p=1`) для создания 256-битного ключа из мастер-пароля и соли.
    *   **Шифрование**: Использовать AES-256-GCM.
    *   **Формат данных**: Результат шифрования должен быть упакован в одну Base64 строку с префиксом:
        `ENC:<base64(соль(16 байт) + nonce(12 байт) + tag(16 байт) + ciphertext)>`.
    *   **Безопасность памяти**: Реализовать `Zeroize` для всех структур, хранящих пароли, мастер-ключи и промежуточные буферы расшифровки.

3.  **Интеграция в загрузчик (./src/config/loader.rs)**:
    *   При парсинге данных из `./global.toml`, `./exchange.toml` или `.env` проверять наличие префикса `ENC:`.
    *   **Критично**: Если префикс обнаружен, а переменная окружения `NEIRO_MASTER_KEY` отсутствует или пуста — бот должен завершить работу с **Fatal Error** (запрещен fallback на открытый текст).

4.  **CLI Утилита (./src/bin/crypto_tool.rs)**:
    *   Создать инструмент для пользователей, позволяющий зашифровать сырой ключ.
    *   Команда: `cargo run --bin crypto_tool --encrypt "my_secret"`.

### Б. Тестирование (./tests/crypto_tests.rs)
*   Реализовать тесты на:
    1.  **Roundtrip**: Зашифровал -> Расшифровал -> Получил исходник.
    2.  **Tamper Detection**: Изменение одного бита в Base64 строке должно приводить к ошибке аутентификации (GCM tag failure).
    3.  **Invalid Key**: Попытка расшифровки с неверным мастер-паролем должна возвращать ошибку, а не мусор.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о деривации ключа**: Согласен с Grok. Прямое использование пароля как ключа шифрования недопустимо. Argon2id — современный стандарт, устойчивый к GPU-перебору и side-channel атакам.
*   **Спор о формате данных**: Конкатенация соли и nonce в одну строку `ENC:` делает секрет самодостаточным (portable), что упрощает перенос конфигов между серверами.
*   **Спор о Zeroize**: В HFT-боте мастер-ключ может находиться в памяти долго. Использование `Zeroize` гарантирует, что даже при дампе памяти (core dump) или эксплойте `heartbleed-style` секреты не утекут в открытом виде.

## 4. Ожидаемый результат
Все API-секреты в файлах выглядят как `ENC:Afd7...`. Бот запускается только при наличии `NEIRO_MASTER_KEY` в окружении. Память очищается сразу после расшифровки конфигурации.
