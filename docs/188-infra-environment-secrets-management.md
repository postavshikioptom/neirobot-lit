# [./docs/188-infra-environment-secrets-management.md](./docs/188-infra-environment-secrets-management.md)

## 1. Описание задачи
Внедрение системы управления секретами (API-ключи) через переменные окружения и `.env` файлы с обязательным маскированием данных в логах. Это предотвращает случайную утечку ключей в публичные репозитории или логи системы.

## 2. Детали реализации

- **Библиотеки**: Использовать `dotenvy` для загрузки переменных и `serde` для маппинга.
- **Точка входа**: Добавить `dotenvy::dotenv().ok()` в начало `main()` в [./src/bin/run-bot.rs](./src/bin/run-bot.rs).
- **Маскирование логов**:
    - В [./src/utils/logger.rs](./src/utils/logger.rs) (или аналогичном модуле логгера) реализовать `SecretMasker`.
    - Список строк для маскирования должен подтягиваться из считанных секретов (`BYBIT_API_KEY`, `BYBIT_API_SECRET`).
    - Заменять ключи в выводе на `[MASKED]`.
- **Приоритет конфигурации**:
    - Переменные окружения должны иметь **высший приоритет** и перекрывать значения из `bot.toml` (обновить [./src/config/loader.rs](./src/config/loader.rs)).
- **Безопасность**:
    - Обновить `.gitignore`, добавив `.env` и `*.env.*`.
    - Добавить файл-шаблон `.env.example` с пустыми значениями.

## 3. Интеграция в код
```rust
// src/bin/run-bot.rs
fn main() {
    dotenvy::dotenv().ok(); // Загрузка .env
    let api_key = std::env::var("BYBIT_API_KEY").expect("BYBIT_API_KEY must be set");
    // ... передача в конфиг
}
```

## 4. Ожидаемый результат
1. Бот успешно стартует, используя ключи из `.env`.
2. В логах при выводе конфига или ошибок API-ключи заменяются на `***`.
3. Отсутствие секретов в репозитории подтверждается `.gitignore`.
