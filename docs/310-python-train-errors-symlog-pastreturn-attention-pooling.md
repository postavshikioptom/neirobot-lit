## Корневая причина проблемы

**UNDERFITTING - Недостаточная емкость модели (Model Capacity)**

Модель с `d_model=64` пытается сжать 300 входных признаков в 64-мерное пространство. Это слишком агрессивное сжатие, которое приводит к потере критически важной информации о микроструктуре стакана.

### Подтверждение из исследований:

Из анализа best practices для LOB данных ([источник](https://kniyer.substack.com/p/the-plumbing-beneath-the-price-order)):
- Order Flow Imbalance (OFI) предсказывает движение цены на ~20 тиков раньше
- Глубокие уровни стакана содержат важную информацию о ликвидности
- Трансформеры для финансовых данных требуют достаточной capacity для выучивания сложных паттернов

# АНАЛИЗ ZenCoder-1
Я принимаю вызов. Если мы фокусируемся на **LiT (Limit Order Book Transformer)** и одном горизонте в 100 тиков, то простое увеличение параметров (как предложил Kiro) — это "стрельба из пушки по воробьям", которая не лечит болезнь, а маскирует симптомы.

### Почему 0.04% Threshold и `d_model=128` от Kiro не сработают сами по себе:
Если при 58% Flat у нас MCC всего 0.02, это значит, что модель **вообще не различает Up и Down**. Она путает их. Увеличение голов с 4 до 8 просто заставит 8 голов смотреть на один и тот же "белый шум" стакана.

### Мой контраргумент и предложение:
Ты спросил про **Dual Attention**. Объясняю на пальцах, почему это критично для LiT:
В обычном трансформере (как сейчас у нас) все 300 признаков (6 каналов * 50 уровней) сваливаются в одну кучу. Модель пытается найти зависимости между "Объемом на 50-м уровне Ask" и "Past Returns". Это создает **комбинаторный взрыв шума**.

**Мое предложение (вместо "просто больше голов"):**
Внедрить **Spatial-Temporal Attention (Пространственно-Временное Внимание)**. Это и есть суть современных LOB-трансформеров (например, из статьи *LiT: Limit Order Book Transformer, 2023/24*).

#### Задача 311: Внедрение Cross-Level Feature Interaction (Spatial Embedding)
*   **Что это**: Вместо того чтобы сразу кидать всё в Transformer, мы добавляем `Linear(300 -> d_model)` не для всей пачки, а делаем **Patching** по уровням. 
*   **Зачем**: Чтобы модель сначала поняла структуру "цены-объемы" внутри одного снимка стакана, а уже потом Transformer искал зависимости во времени (между 100 тиками).
*   **Почему Kiro не прав**: Он хочет увеличить `d_model` до 128, но это раздует `Linear` слой, и он всё равно будет пытаться выучить всё сразу. Нам нужно **сначала сжать пространство (Spatial), потом расширить время (Temporal)**.

## Мой диагноз: 4 критические проблемы (в порядке приоритета)

### Проблема #1: 🔴 PastReturns = 0.0 (МЁРТВЫЙ КАНАЛ)

**Что показывает output.txt:**
```
Channel 5 (PastRet): min=0.0000, max=0.0000, mean=0.0000
```

**Причина в коде** ([dataset.py](file:///e:/MAX/PYTHON/NEURAL-BOTS/neirobot-lit/python_lab/src/dataset.py), строки 847-852):

```python
# 3. Расчет PastRet
log_p = np.log(np.maximum(raw_prices, 1e-9))
self.past_ret_cache = np.zeros(len(log_p), dtype=np.float32)
lag = 100
if len(log_p) > lag:
    self.past_ret_cache[lag:] = (log_p[lag:] - log_p[:-lag]).astype(np.float32)
```

Расчёт выглядит правильным. Но дальше в [_process_sample()](file:///e:/MAX/PYTHON/NEURAL-BOTS/neirobot-lit/python_lab/src/dataset.py#1237-1322) (строка 1301):

```python
if idx is not None and hasattr(self, 'past_ret_cache') and self.past_ret_cache is not None:
    r_seq = self.past_ret_cache[idx : idx + self.seq_len]
```

**Проблема**: `past_ret_cache` **нормализуется через Normalizer** (строки 854-866), который использует `Robust Scaler`. Если данные уже были `symlog`-трансформированы или параметры нормализации вычислены некорректно на почти-нулевых данных, то результат может быть сжат до нуля.

Но **главная проблема** в другом месте. Смотрим [_process_sample()](file:///e:/MAX/PYTHON/NEURAL-BOTS/neirobot-lit/python_lab/src/dataset.py#1237-1322) финальную строку (1319):

```python
x_final = symlog_transform(x_final)  # <--- ДВОЙНАЯ ТРАНСФОРМАЦИЯ!
```

`imb_ch` уже прошёл через `symlog_transform()` на строке 1269. А потом **весь тензор** x_final (включая imb_ch) проходит через `symlog_transform()` ещё раз на строке 1319! 

**Для PastReturns**: данные прошли `Normalizer` (Robust), потом `symlog_transform`. Если после Robust нормализации значения лежат в [-1, 1], то `symlog_transform` сжимает их ещё сильнее, потенциально до почти-нуля.

Вывод: **Нужно проверить что конкретно выдаёт Normalizer для past_ret и vib, и убрать двойную symlog-трансформацию**.

### Проблема #2: 🔴 Двойная SymLog-трансформация

В [_process_sample()](file:///e:/MAX/PYTHON/NEURAL-BOTS/neirobot-lit/python_lab/src/dataset.py#1237-1322):
1. **Строка 1269**: `imb_ch = symlog_transform((bid_v - ask_v) / denom)` — imbalance уже трансформирован
2. **Строка 1319**: `x_final = symlog_transform(x_final)` — всё, включая imb_ch, трансформируется повторно

Это означает:
- **imb_ch** получает двойной symlog — сигнал сжимается дважды
- **price_ch, vol_ch** получают один symlog — нормально
- **ofi_ch, vib_ch, pr_ch** получают один symlog — нормально

**Решение**: либо убрать symlog со строки 1269, либо убрать со строки 1319 и применять symlog только к тем каналам, которым он нужен.

### Проблема #3: 🟡 LOBPatching уничтожает пространственную информацию через `.mean(dim=2)`

В [layers.py](file:///e:/MAX/PYTHON/NEURAL-BOTS/neirobot-lit/python_lab/src/layers.py), строка 97:

```python
x_snapshot = x_patched.mean(dim=2)  # (B, S, num_patches, d_model) -> (B, S, d_model)
```

50 патчей (один на каждый уровень стакана) **усредняются** в один вектор.

**Это проблема, потому что:**
- Усреднение стирает разницу между ближними (1-5) и дальними (40-50) уровнями
- `level_pos_emb` добавляет позиционную информацию, но после `mean()` она теряется
- Трансформер получает 100 "снимков стакана", но каждый снимок — это **среднее** по всем уровням

**Однако это НЕ главная причина MCC=0.02.** Даже с `.mean()` модель должна хотя бы немного различать направление. Проблемы #1 и #2 важнее.

ZenCoder прав, что это проблема, но его решение (Spatial Attention) — overkill. Более простое решение:
- Заменить `mean` на `weighted_sum` с обучаемыми весами
- Или использовать `attention pooling` по уровням
