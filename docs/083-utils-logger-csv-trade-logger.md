Задача 083: Реализация CSV-логгера сделок (Trade Logger)
Цель: Создать асинхронную систему сохранения детальной истории сделок и сигналов в CSV-файл для аудита, анализа качества инференса и сверки с бэктестом.

1. Изменения в Cargo.toml
Добавить зависимость: csv = "1.3".
Убедиться в наличии: serde = { version = "1.0", features = ["derive"] }, chrono = "0.4".
2. Реализация в ./src/utils/trade_logger.rs
Структура TradeRecord:
#[derive(Serialize)]
pub struct TradeRecord {
    pub time: String,            // RFC3339 (chrono::Utc::now().to_rfc3339())
    pub symbol: String,
    pub side: String,            // "Buy" / "Sell"
    pub price: Decimal,
    pub qty: Decimal,
    pub order_type: String,      // "Limit" / "Market"
    pub is_maker: bool,
    pub signal_up: f32,          // Вероятность Up
    pub signal_down: f32,        // Вероятность Down
    pub realized_pnl: Option<Decimal>, // Только при закрытии/сокращении
    pub fee: Decimal,
}
Асинхронный логгер (CsvTradeLogger):
Канал (MPSC): Использовать tokio::sync::mpsc::channel<TradeRecord>(1000). Ограничение (bounded) в 1000 записей защищает память при зависании диска.
Фоновая задача: В методе init() запускать tokio::spawn(async move { ... }).
Запись и Flush: Внутри задачи:
Открыть файл в режиме append.
При получении записи из канала: записать строку CSV и немедленно вызвать writer.flush(). Это гарантирует сохранность данных при внезапном падении бота.
Заголовки: Если файл пустой/создан впервые, записать строку заголовков (headers).
3. Интеграция
Инициализация: В main.rs или run_bot (задачи 045-046) создать инстанс логгера и передать Sender<TradeRecord> в PositionManager и Execution.
Точки логирования:
Fill Event: В PositionManager при обработке исполнения (задача 064) формировать запись.
PnL: При закрытии позиции передавать рассчитанный realized_pnl (задача 070).
Shutdown: При получении сигнала завершения (SIGINT/SIGTERM, задача 084) дождаться обработки всех сообщений в канале перед закрытием дескриптора файла.
4. Почему этот план лучше (Аргументы Grok):
Immediate Flush: Торговые события (сделки) происходят не миллионы раз в секунду. Вызов flush() после каждой записи имеет пренебрежимо малую нагрузку, но критически важен для финансовой отчетности.
RFC3339: Стандартный формат ISO-8601 (с таймзоной Z), который легко читается как Python (Pandas), так и Excel/Tableau.
Bounded Channel: Защита от утечки памяти. Если диск станет недоступен (например, переполнен), канал заполнится и бот выдаст ошибку, вместо того чтобы бесконечно копить записи в RAM.
Option PnL: Удобно разделять записи об открытии (PnL = None) и о закрытии (PnL = Some).
5. Тестирование
Non-blocking test: Убедиться, что отправка 1000 записей в логгер не замедляет цикл Inference (проверка через tokio::time::Instant).
Data Integrity: Проверить, что после внезапного kill -9 последние записанные в канал сделки успели попасть в CSV файл (за счет flush).
