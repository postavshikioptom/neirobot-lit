# Анализ и исправление задачи 149

## Текущие проблемы в описании Задачи 149

1. **Отсутствие реализации (Feature Missing)**: Задача 149 («Large Order Slicing») написана как *тестовая* задача, но сам механизм нарезки ордеров (slicing) еще не реализован в коде (`execution.rs`). В конфигах нет параметра `max_slice_size`.
2. **Несуществующие зависимости**:
    - Упоминается файл `tests/full_pipeline_mock.rs`, который якобы был создан в задаче 050.
    - На самом деле задача 050 создала `tests/execution_flow.rs`.
    - Упоминается структура `FullBotMock` с методами `inject_ml_signal`, `wait_for_order_placed`, которых нет в текущей тестовой базе.
3. **Смешение зон ответственности**: Задача 149 пытается одновременно проверить логику нарезки и провести стресс-тест (1000 msg/sec), что дублирует функционал задачи 150 (Stress Testing).
4. **Устаревший код в примерах**: Пример кода в `docs/149-...` использует типы и методы, которых не существует.

## Предлагаемые изменения

### 1. Переименование и расширение области (Scope)
Задачу 149 следует превратить из исключительно тестовой в задачу по **реализации и тестированию**.
**Новое название**: "Implement and Test Large Order Slicing mechanism".

### 2. Новый план реализации для задачи 149

#### Фаза 1: Доработка конфигурации
- Добавить `max_slice_size: f64` в `BotConfig` (src/config/types.rs).
- Добавить `default_max_slice_size()` хелпер (например, по умолчанию 0.0, что означает "отключено").

#### Фаза 2: Реализация логики в `ExecutionEngine`
- В `src/trading/execution.rs` изменить логику выставления ордеров.
- Если целевой объем позиции превышает текущий более чем на `max_slice_size`, выставлять ордер только на `max_slice_size`.
- Реализовать механизм "довыставления" (sequential execution): после того как первый слайс исполнен (`OrderState::Filled`), проверять, нужно ли выставить следующий.

#### Фаза 3: Создание инфраструктуры `FullBotMock` (или исправление ссылок)
- Вместо ссылки на несуществующий файл, реализовать в `tests/common/` вспомогательный класс `BotTestHarness`, который позволит:
    - Подавать искусственные сигналы.
    - Эмулировать исполнение ордеров (fills).
    - Ждать изменения состояния.

#### Фаза 4: Функциональное тестирование
- Тест 1: Ордер объемом 5.0 при `max_slice_size = 1.0` должен привести к последовательному появлению 5 ордеров по 1.0.
- Тест 2: Проверка взаимодействия с `RiskManager` для каждого слайса.
- Тест 3: Проверка `RateLimiter` между слайсами.

### 3. Удаление стресс-сценария
- Удалить пункт про "1000 msg/sec" из задачи 149, так как это полностью покрывается задачей 150 в специализированной среде `criterion`.

Необходимо полностью переписать файл документации, чтобы он отражал реальность: сначала внедряем код, потом используем `execution_flow.rs` или новый хелпер для тестов.
