
# Задача 221: Стример баланса и PnL в реальном времени (Real-time Equity Streamer)

## 1. Цель задачи
Реализовать систему потоковой трансляции финансового состояния бота (Equity, PnL, Position) через WebSocket. Система должна обеспечивать мгновенное обновление «нереализованной прибыли» (Unrealized PnL) при движении цены, сохраняя точность за счет периодической синхронизации с реальным балансом биржи.

## 2. Инструкции для Gemini по реализации

### А. Изменения в Rust-ядре (Data & Logic)

1.  **Типы данных ([./src/monitoring/types.rs](./src/monitoring/types.rs))**:
    *   Создать новый файл для структур мониторинга.
    *   `EquityUpdate`: `timestamp`, `total_equity` (баланс + PnL), `unrealized_pnl` (с учетом Taker fee на закрытие), `realized_pnl_day`, `position_size`.

2.  **Position Manager ([./src/trading/position_manager.rs](./src/trading/position_manager.rs))**:
    *   Внедрить `tokio::sync::broadcast::Sender<EquityUpdate>`.
    *   **Расчет**: При каждом изменении `mid_price` пересчитывать `unrealized_pnl`.
    *   **Синхронизация**: Раз в 60 секунд (настраивается) запрашивать баланс через Bybit REST для устранения дрейфа (fees/funding).

3.  **Конфигурация ([./src/config/types.rs](./src/config/types.rs))**:
    *   Добавить в `BotConfig`:
        ```rust
        monitoring_port: u16,      // Например, 9001
        min_update_ms: u64,        // Троттлинг (например, 100мс)
        balance_sync_interval: u64 // Интервал REST-синхронизации (сек)
        ```

### Б. WebSocket Сервер ([./src/bin/run-bot.rs](./src/bin/run-bot.rs))

1.  **Реализация Axum**:
    *   Запустить легковесный `axum` сервер на `127.0.0.1` (строго локально).
    *   Эндпоинт `/ws` для трансляции потока из `broadcast` канала в формате JSON.
    *   **Зависимости**: `axum`, `tokio-tungstenite`, `tower-http`.

### В. Изменения в Python Lab (Live Monitor)

1.  **Создать [./python_lab/scripts/live_equity_viewer.py](./python_lab/scripts/live_equity_viewer.py)**:
    *   Клиент на `websockets` + `plotext` (терминальная графика).
    *   Отображение живого графика Equity без нагрузки на дисковую подсистему.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор об эндпоинте**: Согласен с Grok. Ссылки на задачу 135 были ошибочны. Использование `axum` для создания выделенного WS-порта — самое чистое и масштабируемое решение.
*   **Спор о дрейфе (Drift)**: Полностью согласен. Нереализованный PnL, считаемый только по стакану, постепенно расходится с реальностью из-за комиссий и фандинга. REST-синхронизация раз в минуту «якорит» данные к истине.
*   **Спор о безопасности**: Привязка к `127.0.0.1` критична. Мы транслируем финансовые данные в открытом JSON, они не должны покидать пределы локальной машины/контейнера.

## 4. Ожидаемый результат
Запуск скрипта визуализации дает мгновенный отклик: вы видите, как меняется ваш баланс с каждым тиком стакана. В логах `security_audit.csv` фиксируется факт подключения к мониторингу.
