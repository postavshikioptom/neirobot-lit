# Задача 219: Автоматический процесс-вотчдог (Automatic Process Watchdog)

## 1. Цель задачи
Реализовать систему мониторинга «живучести» (Liveness) и автоматического восстановления бота. Система должна обнаруживать как полное завершение процесса (Crash), так и логическое зависание (Deadlock) основного торгового цикла.

## 2. Инструкции для Gemini по реализации

### А. Внутренний механизм Liveness (Rust)

1.  **Heartbeat из критического пути ([./src/bin/run-bot.rs](./src/bin/run-bot.rs))**:
    *   **НЕ использовать** отдельный поток для Heartbeat (он не заметит зависание основного цикла).
    *   Реализовать обновление файла `bots/SYMBOL/state/liveness.heartbeat` **внутри основного Trading Loop** (раз в N итераций или через асинхронный интервал внутри основной задачи).
    *   Файл должен содержать только Unix Timestamp. Права доступа: `640`.

2.  **Безопасный Panic Hook ([./src/main.rs](./src/main.rs))**:
    *   Установить `std::panic::set_hook`.
    *   **Ограничение**: Использовать хук **только для записи Backtrace** в `bot.log`. 
    *   **НЕ пытаться** сохранять состояние (IO) внутри хука — это может привести к Deadlock. Полагаться на периодическое сохранение из задачи 218.

3.  **Очистка при старте**:
    *   При инициализации бот должен проверять наличие старого `liveness.heartbeat`. Если он старше 1 минуты — логировать как «Recovery после сбоя». Перед началом цикла обновить/пересоздать файл.

### Б. Внешний Watchdog (Shell/Systemd)

1.  **Скрипт мониторинга ([./scripts/bot_watchdog.sh](./scripts/bot_watchdog.sh))**:
    *   Реализовать цикл `while true` с запуском бинарника.
    *   **Ограничение перезапусков**: Добавить счетчик. Если бот упал более 10 раз за 1 час — прекратить попытки и вывести критическую ошибку в `stderr`.
    *   **Exponential Backoff**: Пауза перед рестартом: 5с, 10с, 20с... (макс 60с).

2.  **Systemd конфигурация ([./infra/neirobot@.service](./infra/neirobot@.service))**:
    *   Использовать `Restart=on-failure`.
    *   Настроить `StartLimitIntervalSec=3600` и `StartLimitBurst=10` для аппаратной защиты от бесконечных рестартов.

### В. Инфраструктура
1.  **Git ([./.gitignore](./.gitignore))**:
    *   Добавить `bots/*/state/liveness.heartbeat` в исключения.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о потоке Heartbeat**: Полностью согласен с Grok. Отдельный поток — это «ложное чувство безопасности». Если торговый цикл зависнет на ожидании мьютекса или в бесконечном расчете, отдельный поток продолжит обновлять файл, и мы не узнаем о простое. Heartbeat должен идти из «горячего пути» логики.
*   **Спор о Panic Hook**: Согласен, IO операции в момент паники небезопасны. Мы используем хук только как инструмент посмертного анализа (Backtrace), а за сохранность данных отвечает механизм из 218-й задачи.
*   **Спор о лимитах**: Введение жесткого лимита (10 рестартов в час) — это защита от «сжигания» API-лимитов и блокировки IP биржей при фатальных ошибках в коде или конфиге.

## 4. Ожидаемый результат
Бот защищен от всех типов программных сбоев. Внешний монитор перезапустит его, если процесс упадет, а проверка актуальности `liveness.heartbeat` позволит обнаружить и перезагрузить «зависшего» бота.

---
**Gemini, при реализации в `bot_watchdog.sh`: убедись, что скрипт корректно перехватывает сигналы завершения (SIGTERM), чтобы при плановой остановке через `systemctl stop` он не пытался снова запустить бота.**
