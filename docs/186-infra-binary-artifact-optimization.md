# Задача №186: Оптимизация бинарного артефакта (Binary Artifact Optimization)

**Цель**: Повышение производительности и уменьшение размера бинарного файла бота для лучшей утилизации кеша процессора и снижения задержек. Оптимизация включает настройку профилей компиляции, использование альтернативного аллокатора и специфичных инструкций CPU.

---

## План реализации для Gemini AI Coder:

### 1. Настройка профиля в [./Cargo.toml](./Cargo.toml)
Оптимизировать секцию `[profile.release]` для получения максимально эффективного кода:
- **`opt-level = 3`**: Полная оптимизация скорости.
- **`lto = "fat"`**: Link-Time Optimization по всему графу зависимостей для глубокого инлайнинга.
- **`codegen-units = 1`**: Генерация кода в один поток для более качественной оптимизации.
- **`panic = "abort"`**: Отключение раскрутки стека (Unwinding) для уменьшения размера и ускорения бинарника.
- **`strip = true`**: Удаление отладочных символов (уменьшение размера на 20-50%).

### 2. Использование `mimalloc` в [./src/main.rs](./src/main.rs)
Заменить стандартный аллокатор для снижения фрагментации памяти и ускорения аллокаций в HFT-контуре:
- **Зависимости**: Добавить `mimalloc = "0.1"` в [./Cargo.toml](./Cargo.toml).
- **Реализация**:
  ```rust
  use mimalloc::MiMalloc;

  #[global_allocator]
  static GLOBAL: MiMalloc = MiMalloc;
  ```

### 3. Инструкции по сборке (RUSTFLAGS)
Добавить в [./README.md](./README.md) или документацию инструкции по сборке с использованием флагов процессора и быстрого линкера:
- **Команда**: `RUSTFLAGS="-C target-cpu=native -C link-arg=-fuse-ld=lld" cargo build --release`.
- **Цель**: Использование расширенных наборов инструкций (AVX/AVX-512) и ускорение этапа линковки.

### 4. Внутренняя оптимизация (Inlining)
Проставить атрибуты `#[inline(always)]` на критических путях исполнения (Hot Paths) для минимизации накладных расходов на вызов функций:
- **Модули**: [./src/data/orderbook.rs](./src/data/orderbook.rs), [./src/trading/execution.rs](./src/trading/execution.rs), [./src/risk/risk_manager.rs](./src/risk/risk_manager.rs).

### 5. Валидация
- **Сборка**: Выполнить `cargo build --release --verbose` и убедиться в применении LTO и отсутствии отладочных символов.
- **Размер**: Сравнить размер бинарного файла до и после оптимизаций (ожидаемое уменьшение на 20-40%).

## Аргументация (согласно замечаниям Grok):
1. **Локация флагов**: Флаги сборки `RUSTFLAGS` вынесены в инструкции, так как скрипты деплоя появятся в более поздних фазах проекта.
2. **Аллокатор**: `mimalloc` от Microsoft обеспечивает стабильную работу с памятью в многопоточных приложениях, минимизируя "заикания" (stutters) при частых аллокациях.
3. **Panic Abort**: Для торгового бота паника — фатальное событие. Отключение `unwind` делает код более прямолинейным и компактным, что критично для микросекундного инференса.
4. **LTO Fat**: Несмотря на увеличение времени компиляции, этот режим позволяет компилятору оптимизировать вызовы между всеми зависимостями (например, между `onnxruntime` и логикой бота).
