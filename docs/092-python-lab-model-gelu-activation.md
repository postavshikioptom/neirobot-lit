
# Задача 092: Оптимизация функций активации (GELU/SiLU)

**Цель**: Внедрить современные функции активации (**GELU**, **SiLU**) в архитектуру модели для улучшения сходимости и способности сети обрабатывать зашумленные данные LOB.

## 1. Изменения в Python-лаборатории ([./python/](./python/))

### 1.1. Изменения в `lit_model.py`
*   **Универсальный выбор**: Добавить возможность выбора активации через конфигурацию модели.
*   **Слои**: Заменить `nn.ReLU()` во всех частях архитектуры:
    *   В блоках `TransformerEncoder`.

*   **Поддерживаемые типы**:
    *   `GELU (exact)` — стандартная (через `erf`).
    *   `GELU (tanh)` — аппроксимированная (для потенциального ускорения инференса).
    *   `SiLU (Swish)` — часто показывает лучшие результаты в глубоких сетях.

## 2. Экспорт и Rust-интеграция
*   **ONNX Opset**: При экспорте использовать `opset_version=14+` для нативной поддержки `GELU` и `SiLU`.
*   **Валидация экспорта**: Запустить `export_onnx.py` для каждой активации и проверить в `Netron`, что операторы не разложены на примитивы (что замедляет инференс), а представлены едиными узлами.
*   **Паритет (Rust)**: Расширить тест паритета (задача 038). Разница между предсказаниями в Python и Rust должна быть `< 1e-6` для всех типов активаций.

## 3. Почему этот план лучше (Аргументы Grok):
*   **Exact vs Tanh**: Современное оборудование (CPU/GPU) эффективно вычисляет `erf`, поэтому `GELU (exact)` может быть точнее без потери скорости. Наличие обоих вариантов позволяет выбрать лучший.
*   **SiLU (Swish)**: Добавление `SiLU` как альтернативы важно, так как она часто превосходит `GELU` в задачах регрессии и классификации на временных рядах.
*   **Grad Flow**: GELU и SiLU имеют ненулевой градиент для отрицательных значений, что предотвращает проблему "мертвых нейронов", характерную для ReLU при работе с нормализованными (Z-score) данными стакана.

## 4. Критические требования
*   **Consistency**: Выбранная активация должна применяться ко всем слоям модели одновременно.
*   **No Hardcode**: Все параметры активации должны передаваться через `model_config`.
*   **Measurement**: Результаты MCC фиксируются в логах обучения для каждой конфигурации.

## 5. Тестирование
*   **Gradient Check**: Убедиться, что градиенты не затухают при подаче сильно отрицательных тензоров.
*   **Parity Test**: Сравнение выводов `lit_model` и `ort_session` на наборе из 1000 случайных снимков стакана.
