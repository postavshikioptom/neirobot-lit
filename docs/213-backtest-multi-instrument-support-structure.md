
# Задача 213: Структура поддержки мульти-инструментальности (Multi-Instrument Support Structure)

## 1. Цель задачи
Реализовать в бэктестере возможность одновременной обработки данных по нескольким торговым парам. Система должна объединять потоки данных в единую хронологическую последовательность, сохраняя при этом полную изоляцию логики и настроек для каждого символа.

## 2. Инструкции для Gemini по реализации

### А. Загрузка и слияние данных (Polars Stream)
1.  **Обновить `./python_lab/src/dataset.py`** (или расширить его функционал):
    *   Реализовать поддержку списка символов `symbols: List[str]`.
    *   **Метод слияния**:
        ```python
        import polars as pl
        # Загрузка нескольких Parquet через lazy API
        scans = [pl.scan_parquet(f"bots/{s}/data/raw/*.parquet").with_columns(pl.lit(s).alias("symbol")) for s in symbols]
        # Объединение и глобальная сортировка по времени для предотвращения Look-ahead bias
        merged_stream = pl.concat(scans).sort("timestamp").collect().iter_rows(named=True)
        ```
2.  **ВАЖНО**: Слияние должно быть строго детерминированным. Если временные метки совпадают, порядок символов должен быть фиксированным.

### Б. Работа с конфигурациями (tomllib)
1.  **Загрузка настроек**:
    *   Использовать стандартную библиотеку `tomllib` (для Python 3.11+) или `tomli` для загрузки индивидуальных файлов конфигурации: `./bots/SYMBOL/config.toml`.
    *   Каждый инструмент должен иметь свой экземпляр настроек, идентичный Rust-структуре `BotConfig`.

### В. Архитектура движка и Изоляция
1.  **Обновить `./python_lab/src/backtest/engine.py`**:
    *   Все внутренние состояния (`OrderBook`, `PositionManager`, `QueueTracker`) должны храниться в словарях с ключом по символу: `self.states: Dict[str, SymbolState]`.
    *   **Риск-менеджмент**: Проверки лимитов (Max Position, Drawdown) должны выполняться **строго индивидуально** для каждого символа, без объединения в общий портфель (согласно архитектуре проекта).

### Г. Вывод данных (CSV)
1.  **Логирование**:
    *   В выходной файл `backtest_trades.csv` добавить обязательную колонку `symbol` на первой позиции.
    *   Обеспечить идентичность формата с живыми логами из задачи 201.

## 3. Критика и аргументация (По правкам Grok)
*   **Спор о портфеле**: Полностью согласен с Grok. Проект строится на изоляции токенов. Введение общего риск-менеджмента на данном этапе избыточно и нарушает принцип «один бот — один процесс».
*   **Спор о `dataset.py`**: Использование существующего файла `dataset.py` для расширения логики загрузки данных — архитектурно правильное решение, сохраняющее чистоту структуры `src/`.
*   **Спор о `tomllib`**: Переход на стандартный `tomllib` избавляет от лишних внешних зависимостей и гарантирует совместимость с современными версиями Python.
*   **Спор о слиянии**: Использование `pl.concat([...]).sort("timestamp")` эффективнее, чем ручной `heapq.merge`, так как Polars оптимизирует работу с памятью и многопоточность при чтении Parquet.

## 4. Ожидаемый результат
