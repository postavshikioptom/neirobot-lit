# Задача 205: Автоматизированные ежедневные PnL-отчеты (Automated Daily PnL Reports)

## 1. Цель задачи
Создать систему ежедневной отчетности, которая объединяет данные об исполнении (Rust-логи) с реальным состоянием счета на бирже (Bybit REST). Отчет должен содержать ключевые риск-метрики (Sharpe, MaxDD) для оценки качества работы бота.

## 2. Инструкции для Gemini по реализации

### А. Изменения в Rust-ядре (Data Source Sync)

1.  **Синхронизация с балансом ([./src/trading/rest_client.rs](./src/trading/rest_client.rs))**:
    *   Реализовать периодический (раз в 1–5 минут) запрос к эндпоинту Bybit `/v5/account/wallet-balance`.
    *   Получать `totalEquity`, `availableBalance` и `usedMargin`.
    *   **ВАЖНО**: Не полагаться только на оценку позиции по `mid_price` (избегаем ошибок округления и плавающих комиссий).

2.  **Логирование Equity ([./src/utils/logger.rs](./src/utils/logger.rs))**:
    *   Записывать данные в **`equity.csv`** в папке бота.
    *   **Колонки**: `timestamp`, `rest_equity`, `rest_margin`, `local_unrealized_pnl` (на основе стакана), `total_pnl_delta`.

### Б. Изменения в Python Lab (Advanced Analytics)

1.  **Создать [./python_lab/scripts/daily_report.py](./python_lab/scripts/daily_report.py)**:
    *   **Функционал**: Скрипт должен поддерживать запуск вручную, по крону или через вызов из Rust при `on_exit`.
    *   **Библиотеки**: Использовать `polars` для обработки и `empyrical` (или ручную реализацию) для метрик.
    *   **Список обязательных метрик**:
        *   **Net PnL**: Чистая прибыль (учитывая разницу REST баланса).
        *   **Sharpe Ratio**: Коэффициент Шарпа (риск-скорректированная доходность).
        *   **Max Drawdown**: Максимальная просадка за период.
        *   **Calmar Ratio**: Отношение доходности к просадке.
        *   **Win Rate**: % прибыльных сделок.
        *   **Slippage Leakage**: Сколько прибыли "утекло" из-за задержек (из задачи 201).

2.  **Формат вывода**:
    *   Генерировать **`reports/daily_YYYYMMDD.json`** для UI/Dashboards.
    *   Генерировать **`reports/daily_YYYYMMDD.md`** (краткая сводка для человека).

## 3. Критика и аргументация (По правкам Grok)
*   **Спор об источнике Equity**: Полностью согласен с Grok. Использование только `mid_price` для оценки PnL — это путь к накоплению ошибок. REST-запрос баланса раз в несколько минут дает «якорь истины».
*   **Спор о метриках**: Расширяем список до индустриальных стандартов (Sharpe/Calmar). Это позволит сравнивать разных ботов/символы между собой.
*   **Спор о триггерах**: Скрипт в Python должен быть независимым. Бот может посылать сигнал на его запуск, но скрипт должен уметь работать автономно по расписанию UTC 00:00 (Daily Rollover).

## 4. Ожидаемый результат
Ежедневный файл-отчет, который показывает не только «сколько заработали», но и «какой ценой»: с какой просадкой и сколько мы потеряли на комиссиях и латентности.
