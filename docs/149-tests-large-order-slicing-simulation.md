# Задача 149: Реализация и тестирование механизма нарезки крупных ордеров (Slicing)

## 1. Цель
Реализовать механизм автоматического разбиения (нарезки) крупных торговых заявок на более мелкие части («слайсы») для минимизации рыночного влияния и соблюдения лимитов. Обеспечить последовательное исполнение слайсов с проверкой рисков и соблюдением лимитов частоты запросов (Rate Limiting).

## 2. План реализации

### 2.1. Конфигурация
1.  **BotConfig**: Добавить поле `max_slice_size: f64` в `src/config/types.rs`.
    - Если `max_slice_size > 0`, активируется механизм нарезки.
    - Добавить `default_max_slice_size() -> f64 { 0.0 }`.

### 2.2. Изменения в ExecutionEngine (`src/trading/execution.rs`)
1.  **Логика планирования**:
    - В методе `on_inference_output` (или при расчете целевого объема), если требуемое изменение позиции превышает `max_slice_size`, ограничить объем текущего ордера величиной `max_slice_size`.
2.  **Последовательное исполнение**:
    - Реализовать механизм ожидания завершения предыдущего слайса.
    - Новый ордер на следующий слайс должен выставляться только после того, как текущий ордер перешел в терминальное состояние `Filled` (или `Cancelled` с частичным набором).
3.  **Интеграция с RiskManager**:
    - Каждый отдельный слайс должен проходить проверку `RiskManager::can_place_order`.

### 2.3. Тестовая инфраструктура (`tests/common/mod.rs`)
1.  **BotTestHarness**: Создать структуру для удобного интеграционного тестирования:
    - Метод `inject_signal(signal, prob)` — подача сигнала в движок.
    - Метод `emulate_fill(link_id, qty)` — эмуляция исполнения ордера.
    - Метод `wait_for_order()` — ожидание появления нового ордера в менеджере.

## 3. План тестирования

### 3.1. Функциональные тесты (`tests/slicing_integration_tests.rs`)
1.  **Scenario: Simple Slicing**:
    - Установить `max_slice_size = 1.0`. Подать сигнал на покупку 3.5 единиц.
    - Проверить, что сначала выставляется ордер на 1.0.
    - После эмуляции `Filled` первого ордера, должен автоматически выставиться второй на 1.0, и так далее до полного объема.
2.  **Scenario: Risk Block during Slicing**:
    - Убедиться, что если в процессе набора слайсов `RiskManager` возвращает ошибку (например, достигнут `max_drawdown`), процесс нарезки останавливается.
3.  **Scenario: Rate Limiter Safety**:
    - Проверить, что паузы между выставлением слайсов соответствуют настройкам `RateLimiter`.

## 4. Критерии приемки
- [ ] Параметр `max_slice_size` добавлен в конфиг и корректно загружается.
- [ ] Крупные ордера разбиваются на части, не превышающие лимит слайса.
- [ ] Каждый следующий слайс выставляется только после подтверждения исполнения предыдущего.
- [ ] Интеграционные тесты в `tests/slicing_integration_tests.rs` успешно проходят.
- [ ] Логи содержат информацию о прогрессе нарезки: `Slicing order: 1.0 / 3.5 total`.
