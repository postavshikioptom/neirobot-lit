# Задача №152: Оценка важности признаков методом перестановки (Permutation Importance)

Согласно [./docs/000-architecture.md](./docs/000-architecture.md), мы должны оптимизировать входной тензор для минимизации задержек. Метод перестановки позволит выявить неинформативные уровни стакана и каналы данных.

## План реализации для Gemini AI Coder:

### 1. Интеграция и загрузка (на базе задачи 021)
*   **Загрузчик**: Использовать `get_val_loader` из [./python_lab/src/dataset.py](./python_lab/src/dataset.py).
*   **Важно**: Отключить `shuffle` в загрузчике (`shuffle=False`), чтобы иметь фиксированный порядок сэмплов для глобальной перестановки.
*   **Состояние**: Анализ проводить **после** нормализации Z-score (задача 024), чтобы данные соответствовали тому, что модель видит в реальном инференсе.

### 2. Логика глобальной перестановки (Global Shuffle)
Не соглашаться на перемешивание внутри батча. Реализовать перемешивание по всему валидационному набору:
1.  Собрать весь валидационный тензор `X_val` (shape: `[N, seq_len, features]`).
2.  Для каждого индекса признака `f`:
    *   Создать `perm = torch.randperm(N)`.
    *   `X_perm = X_val.clone()`
    *   `X_perm[:, :, f] = X_val[perm, :, f]` — перемешиваем значения признака `f` между всеми сэмплами, сохраняя временную структуру внутри `seq_len`.
    *   Повторить `n_repeats` раз для расчета `mean` и `std` падения метрики.

### 3. Групповой анализ (Grouped Importance)
Реализовать маскирование для оценки групп признаков:
*   **Группы**: `Price Levels` (все уровни цен), `Volume Levels` (все объемы), `Spread/Imbalance`.
*   **Метод**: Перемешивать сразу все индексы признаков, входящих в группу. Это покажет, можно ли, например, полностью отказаться от цен и оставить только объемы/дисбаланс.

### 4. Метрики и статистика
*   **Основная метрика**: Только **MCC** (задача 051). Игнорировать Accuracy.
*   **Результат**: Сохранять в `bots/SYMBOL/model/feature_importance.json` список, отсортированный по убыванию `mean_importance`, с указанием `std_dev`.

### 5. Визуализация в [./python_lab/src/utils.py](./python_lab/src/utils.py)
Добавить два типа графиков:
1.  **Bar Chart**: Топ-20 индивидуальных признаков с "усами" погрешности (`std`).
2.  **LOB Heatmap**: Матрица 50 уровней (Y-ось: Level 1-50, X-ось: Ask_V, Ask_P, Bid_V, Bid_P). Интенсивность цвета показывает важность уровня. Это позволит визуально увидеть "горизонт событий" модели.

## Аргументация (Спор с Grok):
*   **Согласен**: Глобальный `randperm` по всему `N` критичен для временных рядов, чтобы избежать случайных корреляций внутри батча.
*   **Согласен**: Перестановка **после** нормализации — единственно верный путь, так как веса модели обучены на конкретных диапазонах Z-score.
*   **Согласен**: Heatmap необходим. В стакане важна пространственная структура (близость к спреду). Обычный список признаков не даст наглядности.
