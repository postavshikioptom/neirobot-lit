# Задача №163: Выход из позиции по времени (Time Decay Exit)

Согласно [./docs/000-architecture.md](./docs/000-architecture.md), микроструктура стакана (LOB) меняется крайне быстро. Сигнал, полученный моделью LiT, имеет ограниченный "срок годности". Мы внедрим механизм **Time Decay**, который будет принудительно закрывать позиции, если они не достигли цели за установленное время.

## План реализации для кодера:

### 1. Изменения в [./src/config/types.rs](./src/config/types.rs)
Добавить параметры в `BotConfig` для гибкой настройки:
```rust
pub struct TimeDecayConfig {
    pub enabled: bool,
    pub max_age_long_ms: u64,
    pub max_age_short_ms: u64,
}
```
Использовать `#[serde(default)]` для сохранения обратной совместимости.

### 2. Обновление [./src/trading/position_manager.rs](./src/trading/position_manager.rs)
Необходимо фиксировать момент возникновения риска:
- **`Position`**: Добавить поле `opened_at: Option<u64>`.
- **`update_from_fill`**: 
    - Если текущая позиция `0` и приходит филл — установить `opened_at = Some(helpers::get_unix_ms())`.
    - Если позиция закрывается в `0` — сбросить в `None`.
- **Метод `is_aged(&self, now: u64, config: &TimeDecayConfig) -> bool`**: Инкапсулировать логику сравнения времени с учетом направления позиции (Long/Short).

### 3. Новый риск-гейт в [./src/risk/risk_manager.rs](./src/risk/risk_manager.rs)
Реализовать проверку как часть системы безопасности (Risk Gate):
- **Метод `check_time_stop(&self, position: &Position) -> bool`**: 
    - Получить текущее время через `helpers::get_unix_ms()` (задача 009).
    - Вызвать `position.is_aged`.
    - Если позиция "протухла" — вернуть `true`.

### 4. Интеграция в основной цикл [./src/bin/run-bot.rs](./src/bin/run-bot.rs)
Проверка должна выполняться на каждом обновлении стакана (OB update):
1. После обновления `OrderBook` вызвать `risk_manager.check_time_stop`.
2. Если гейт сработал — инициировать процедуру **`emergency_market_close`** (задача 109). Это обеспечит мгновенный выход по рынку, игнорируя лимитные стратегии.

### 5. Логирование и аудит
- **Лог**: При срабатывании стопа писать: `[Risk] TIME STOP TRIGGERED: Side: Long, Age: 12450ms, Limit: 10000ms. Executing emergency market close.`.
- **Метрики**: Фиксировать выходы по времени отдельно от обычных стоп-лоссов для анализа качества сигналов.

## Аргументация (Спор с Grok):
- **Согласен**: Time Decay — это защитный механизм, его место в `risk_manager.rs`, а не в торговой стратегии.
- **Согласен**: Разделение `max_age` для лонга и шорта необходимо, так как динамика падения и роста рынка (и, соответственно, стакана) часто асимметрична.
- **Согласен**: Использование `emergency_market_close` — единственный верный способ, так как если время вышло, "умное" лимитное исполнение больше не имеет смысла, нужно немедленно рубить риск.
- **Важное уточнение**: Проверка `is_aged` должна быть максимально дешевой, так как она вызывается сотни раз в секунду. Никаких аллокаций внутри этой функции.

**Gemini, твоя задача — гарантировать, что ни одна сделка не "зависнет" дольше, чем живет её предсказательная ценность.**
