Задача 049-data-orderbook-checksum.md
Цель: Реализовать строгую проверку целостности стакана по алгоритму Bybit V5 (CRC32 IEEE) и механизм автоматической ресинхронизации.

Инструкции для Gemini:
1. Добавление зависимости (Cargo.toml)
Добавить crc32fast = "1.3".
2. Изменения в ./src/data/orderbook.rs
Реализовать метод calculate_checksum(&self) -> u32:
Взять топ-25 Bids (цена по убыванию).
Взять топ-25 Asks (цена по возрастанию).
Для каждого уровня сформировать строку price:size (использовать строковые значения из сообщения биржи или форматирование без лишних нулей).
Соединить все 50 (или меньше) строк через запятую , без пробелов.
Пример строки: 10001.5:0.5,10001:1.0,10002:0.1,10002.5:2.0 (сначала все bids, потом все asks).
Вычислить crc32fast::hash(final_string.as_bytes()).
3. Изменения в ./src/data/websocket.rs
Обработка ошибок: Создать тип ошибки ChecksumMismatch { symbol: String, local: u32, remote: u32 }.
Логика проверки:
После вызова orderbook.apply_delta(update) вызвать orderbook.calculate_checksum().
Сравнить с полем cts из JSON (Bybit V5).
Если не совпадает:
error!("Checksum mismatch for {}: local={}, remote={}", symbol, local, remote).
Вернуть Err(Error::ChecksumMismatch).
Ресинхронизация: При получении этой ошибки основной цикл из задачи 048 должен разорвать соединение.
Важно: Очистка стакана (orderbook.clear()) должна происходить только при получении сообщения type: "snapshot", которое придет первым после переподключения.
4. Изменения в ./src/config/types.rs
Добавить в WebSocketConfig (внутри ExchangeConfig):
pub verify_checksum: bool,
5. Тестирование
Создать юнит-тест в orderbook.rs с реальной строкой и ожидаемым CRC32 из документации Bybit (если доступно) или зафиксированным вручную примером.
Аргументация: Точное следование алгоритму (25 levels, Bids then Asks, comma separator) — единственный способ заставить проверку работать. Использование Error enum обеспечит чистый проброс сигнала на реконнект в задачу 048.
