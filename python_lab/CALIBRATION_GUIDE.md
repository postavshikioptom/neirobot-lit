# Руководство по калибровке модели (Temperature Scaling)

## Обзор

Temperature Scaling - это метод пост-обработки для калибровки вероятностей нейронных сетей. Метод находит оптимальную температуру T, которая минимизирует Negative Log Likelihood (NLL) на валидационной выборке.

## Использование

### 1. Калибровка модели

После обучения модели запустите скрипт калибровки:

```bash
python python_lab/calibrate.py \
    --symbol BTCUSDT \
    --checkpoint bots/BTCUSDT/model/checkpoints/best_model.ckpt \
    --horizon 100 \
    --threshold 0.0005 \
    --batch_size 256
```

Параметры:
- `--symbol`: Символ для калибровки (например, BTCUSDT)
- `--checkpoint`: Путь к checkpoint модели (.ckpt)
- `--horizon`: Горизонт предсказания для меток (по умолчанию 100)
- `--threshold`: Порог для меток (по умолчанию 0.0005)
- `--batch_size`: Размер батча для inference (по умолчанию 256)
- `--initial_temperature`: Начальное значение температуры (по умолчанию 1.5)
- `--max_iter`: Максимальное количество итераций LBFGS (по умолчанию 50)
- `--bins`: Количество корзин для ECE и reliability diagram (по умолчанию 15)

### 2. Результаты калибровки

Скрипт выведет:
- Метрики до калибровки (NLL, ECE)
- Оптимальную температуру
- Метрики после калибровки (NLL, ECE)
- Улучшение метрик в процентах

Также будут созданы:
- `bots/SYMBOL/model/metadata.json` - обновленный файл с температурой
- `bots/SYMBOL/model/reports/reliability_before_calibration.png` - диаграмма до калибровки
- `bots/SYMBOL/model/reports/reliability_after_calibration.png` - диаграмма после калибровки

### 3. Экспорт модели в ONNX

После калибровки экспортируйте модель в ONNX:

#### Вариант A: Встроить температуру в ONNX граф

```bash
python python_lab/src/export_onnx.py \
    --input bots/BTCUSDT/model/checkpoints/best_model.ckpt \
    --output bots/BTCUSDT/model/lit.onnx \
    --embed_temperature
```

В этом случае температура будет встроена в граф ONNX (добавлен узел Div перед Softmax).

#### Вариант B: Применять температуру в Rust

```bash
python python_lab/src/export_onnx.py \
    --input bots/BTCUSDT/model/checkpoints/best_model.ckpt \
    --output bots/BTCUSDT/model/lit.onnx
```

В этом случае модель экспортируется с сырыми логитами, а температура применяется в Rust коде.

### 4. Использование в Rust

Rust код автоматически:
1. Загружает температуру из `metadata.json`
2. Проверяет флаг `temperature_embedded`
3. Если температура не встроена, применяет её к логитам перед Softmax

Никаких дополнительных действий не требуется.

## Метрики калибровки

### Expected Calibration Error (ECE)

ECE измеряет разницу между предсказанной уверенностью модели и фактической точностью:

```
ECE = Σ |accuracy_in_bin - confidence_in_bin| * proportion_in_bin
```

Чем ниже ECE, тем лучше калибровка.

### Negative Log Likelihood (NLL)

NLL - это стандартная функция потерь для классификации. Temperature Scaling минимизирует NLL на валидационной выборке.

### Reliability Diagram

Reliability Diagram показывает соответствие между предсказанной уверенностью и фактической точностью. Идеально калиброванная модель должна лежать на диагонали (y = x).

## Примечания

1. **Калибровка не улучшает точность модели** - она только корректирует уверенность предсказаний
2. **Используйте валидационную выборку** - не используйте тестовую выборку для калибровки
3. **LBFGS оптимизатор** - стандарт для поиска температуры, быстрее и точнее Adam
4. **Гибкость** - температуру можно обновлять без переобучения модели
