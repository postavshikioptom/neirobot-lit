# Руководство по анализу важности признаков (Feature Importance)

## Задача №152: Оценка важности признаков методом перестановки

Этот инструмент позволяет выявить неинформативные уровни стакана и каналы данных для оптимизации входного тензора и минимизации задержек.

## Метод

Используется **Permutation Importance** с глобальной перестановкой по всему валидационному набору:

1. **Загрузка и нормализация данных**:
   - Загружаются валидационные данные через `get_val_loader` или напрямую
   - Применяется Z-score нормализация из `normalization_params.json`
   - Данные должны быть нормализованы так же, как при обучении модели
2. Вычисляется baseline MCC на оригинальных данных
3. Для каждого признака:
   - Перемешиваются значения признака между всеми сэмплами (глобально)
   - Сохраняется временная структура внутри seq_len
   - Вычисляется MCC на перемешанных данных
   - Повторяется n_repeats раз для расчета mean и std
4. Важность = baseline_MCC - permuted_MCC (положительное значение = признак важен)

## Использование

### Базовый запуск

```bash
python python_lab/scripts/feature_importance.py \
  --symbol CAKEUSDT \
  --model_path bots/CAKEUSDT/model/best_model.ckpt
```

### Полный список параметров

```bash
python python_lab/scripts/feature_importance.py \
  --symbol CAKEUSDT \
  --model_path bots/CAKEUSDT/model/best_model.ckpt \
  --data_path bots/CAKEUSDT/data/raw \
  --output_dir bots/CAKEUSDT/model \
  --n_repeats 5 \
  --batch_size 256 \
  --seed 42 \
  --device cuda
```

### Параметры

- `--symbol`: Торговый символ (обязательно)
- `--model_path`: Путь к обученной модели (обязательно)
- `--data_path`: Путь к parquet данным (по умолчанию: `bots/{symbol}/data/raw`)
- `--output_dir`: Директория для сохранения результатов (по умолчанию: `bots/{symbol}/model`)
- `--n_repeats`: Количество повторений перестановки (по умолчанию: 5)
- `--batch_size`: Размер батча для инференса (по умолчанию: 256)
- `--seed`: Random seed для воспроизводимости (по умолчанию: 42)
- `--device`: Устройство для вычислений (по умолчанию: cuda)
- `--skip_individual`: Пропустить анализ индивидуальных признаков
- `--skip_groups`: Пропустить групповой анализ

## Интерпретация результатов

### Индивидуальные признаки

- **Положительная важность**: Признак информативен (MCC падает при перемешивании)
- **Нулевая/отрицательная важность**: Признак неинформативен (можно удалить)
- **Высокий std_dev**: Нестабильная важность (требует дополнительного анализа)

### Групповой анализ

- **Price Levels**: Важность всех уровней цен
- **Volume Levels**: Важность всех объемов
- **Spread/Imbalance**: Важность первого уровня (спред и дисбаланс)
- **Past Returns**: Важность исторических доходностей (если используются)

### Heatmap

- **Яркие области**: Важные уровни стакана
- **Темные области**: Неинформативные уровни (кандидаты на удаление)
- **Синяя линия**: Граница топ-10 уровней

## Оптимизация входного тензора

На основе результатов анализа можно:

1. **Удалить неинформативные уровни**: Если уровни 30-50 имеют низкую важность, можно использовать только первые 30 уровней
2. **Удалить неинформативные каналы**: Если Volume Levels имеет низкую важность, можно оставить только Price
3. **Сфокусироваться на важных признаках**: Использовать только топ-N признаков для ускорения инференса

## Пример оптимизации

Если анализ показал, что:
- Уровни 0-20 имеют высокую важность
- Уровни 21-49 имеют низкую важность
- Volume Levels имеет низкую важность

Можно:
1. Уменьшить n_levels с 50 до 20 в конфигурации
2. Удалить каналы ask_v и bid_v
3. Переобучить модель на оптимизированных данных

Это приведет к:
- Уменьшению размера входного тензора в 2.5 раза
- Ускорению инференса
- Сохранению качества модели (MCC)

## Важные замечания

1. **Глобальная перестановка**: Критична для временных рядов, чтобы избежать случайных корреляций внутри батча
2. **Перестановка после нормализации**: Данные уже нормализованы в датасете, поэтому анализ проводится на тех же данных, что видит модель
3. **Количество повторений**: Рекомендуется n_repeats >= 5 для стабильной оценки std_dev
4. **Время выполнения**: Анализ всех 200 признаков с n_repeats=5 может занять 1-2 часа на GPU

## Troubleshooting

### Out of Memory

Если возникает ошибка OOM:
- Уменьшите `--batch_size`
- Используйте `--skip_individual` для анализа только групп
- Используйте меньшую валидационную выборку

### Медленное выполнение

- Используйте GPU (`--device cuda`)
- Уменьшите `--n_repeats`
- Используйте `--skip_individual` или `--skip_groups`

### Неожиданные результаты

- Проверьте, что модель обучена корректно (baseline_mcc > 0)
- **Убедитесь, что данные нормализованы** (файл `normalization_params.json` должен существовать)
- Увеличьте `--n_repeats` для более стабильной оценки
- Проверьте, что используется правильная модель и данные
