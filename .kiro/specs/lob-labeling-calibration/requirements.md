# Требования: Улучшение качества лабелирования и калибровки LiT модели для скальпинга

## Проблема

Модель LiT для скальпинга криптовалют показывает ужасные результаты:
- **MCC: 0.0041-0.0249** (максимум 2.49%) - практически не различает классы Up/Down
- **Macro-F1: 0.22-0.32** - плохая классификация редких классов
- **ECE: 0.23-0.30** - модель переуверена в своих предсказаниях
- **MCE: 0.54-0.94** - очень плохая калибровка

Распределение меток: Flat 59.6%, Up 20%, Down 20.5% - огромный дисбаланс.

## Корневые причины

1. **Дисбаланс классов 60/20/20** - модель предсказывает Flat для всех примеров
2. **Плохая калибровка вероятностей** - модель не знает, когда она неуверена
3. **Недостаточное взвешивание классов** - Focal Loss есть, но весов может быть недостаточно
4. **Отсутствие аугментации LOB данных** - модель переобучается на шуме

## Бизнес-требования

1. **Улучшить MCC минимум до 0.15-0.20** (с 0.02) - модель должна различать Up/Down
2. **Улучшить Macro-F1 до 0.40-0.50** (с 0.25) - лучше классифицировать редкие классы
3. **Снизить ECE до 0.10-0.15** (с 0.25) - модель должна быть лучше откалибрована
4. **Снизить MCE до 0.30-0.40** (с 0.70) - лучше калибровка для каждого класса

## Функциональные требования

### 1. Улучшенное взвешивание классов
- Вычисление весов на основе обратной частоты класса
- Поддержка сглаживания весов (smoothing factor)
- Возможность ручного задания весов через конфиг
- Логирование распределения весов

### 2. Аугментация LOB данных
- Добавление шума к объемам (volume jitter)
- Случайное удаление уровней стакана
- Симметричное отражение bid/ask
- Параметры аугментации должны быть настраиваемы

### 3. Temperature Scaling для калибровки
- Реализация Temperature Scaling на валидационном наборе
- Сохранение оптимальной температуры в metadata
- Применение температуры при инференсе в Rust

### 4. Анализ качества лабелирования
- Confusion matrix для каждого класса
- Per-class precision, recall, F1
- Анализ распределения меток по времени
- Визуализация reliability diagram

## Нефункциональные требования

1. **Производительность** - обучение должно оставаться быстрым (не более +10% времени)
2. **Совместимость** - не должны ломаться существующие скрипты
3. **Отладка** - подробное логирование всех этапов
4. **Воспроизводимость** - все параметры должны быть сохранены в metadata

## Критерии приемки

1. ✅ MCC улучшен минимум на 50% (с 0.02 до 0.03+)
2. ✅ Macro-F1 улучшен минимум на 30% (с 0.25 до 0.33+)
3. ✅ ECE снижен минимум на 30% (с 0.25 до 0.17 или ниже)
4. ✅ Все параметры сохраняются в metadata.json
5. ✅ Существующие скрипты работают без изменений
6. ✅ Добавлены unit-тесты для новых функций
