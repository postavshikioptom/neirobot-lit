# ИНСТРУКЦИЯ-1: Выгрузка данных и сохранение в Parquet

Данная инструкция описывает процесс запуска выгрузки рыночных данных (LOB/стакан) с биржи Bybit и их сохранение в формате Parquet для последующего обучения моделей.

## 1. Команда запуска

Основным инструментом для выгрузки является бинарный файл `src/bin/dump.rs`. Запуск осуществляется через `cargo`:

```bash
cargo run --release --bin dump -- FARTCOINUSDT --hours 5
```

### Аргументы командной строки:
- `symbol` (позиционный): Тикер инструмента на фьючерсах (например, `FARTCOINUSDT`).
- `--hours` (`-h`): Продолжительность работы утилиты в часах (поддерживается дробная часть, например `0.5` для 30 минут). По умолчанию `1.0`.
- `--config` (`-c`): Путь к конфигу бота. По умолчанию: `bots/SYMBOL/config.toml`.

---

## 2. Прерывание работы (Safe Interruptions)

Выгрузку **можно прерывать в любой момент**, не дожидаясь истечения таймера. 

- Чтобы остановить процесс, просто нажмите `Ctrl+C` в терминале или закройте его.
- **Это ничего не сломает**: код перехватывает сигнал завершения, принудительно записывает все накопленные в оперативной памяти данные («сбрасывает буфер») на диск в последний Parquet-файл и только после этого закрывается. 
- Данные за прошедшее время (до момента прерывания) уже будут сохранены в предыдущих файлах.

---

## 2. Настройки (Конфигурации)

Процесс выгрузки опирается на три основных файла конфигурации:

### 1. `exchange.toml` (Общие настройки биржи)
- `[websocket] public_url`: URL для подключения к Bybit (например, `wss://stream.bybit.com/v5/public/linear`).
- `[rate_limits]`: Лимиты на запросы, чтобы избежать бана IP.

### 2. `global.toml` (Глобальные параметры)
- `[trading_defaults] snapshot_interval_ms`: Интервал фиксации снимка стакана (по умолчанию `100` мс).
- `[logging]`: Уровень детализации логов (рекомендуется `info`).
- `[general] raw_data_retention_days`: Срок хранения сырых данных в днях (задача 187).

### 3. `bots/FARTCOINUSDT/config.toml` (Специфика монеты)
- Содержит индивидуальные параметры для конкретной монеты, если они переопределяют глобальные.

---

## 3. Хранение данных

Данные сохраняются в директорию монеты в формате **Apache Parquet** с компрессией `Zstd`.

- **Путь**: `bots/FARTCOINUSDT/data/raw/`
- **Шаблон имени файла**: `FARTCOINUSDT_TIMESTAMP.parquet` (где TIMESTAMP — время первого снимка в файле).

### Схема данных (203 колонки):
1. `timestamp_ms`: Время получения данных (мс).
2. `last_update_id`: ID последнего обновления от биржи.
3. `symbol`: Тикер.
4. `ask_p_0` — `ask_p_49`: Цены 50 уровней продажи.
5. `ask_v_0` — `ask_v_49`: Объемы 50 уровней продажи.
6. `bid_p_0` — `bid_p_49`: Цены 50 уровней покупки.
7. `bid_v_0` — `bid_v_49`: Объемы 50 уровней покупки.

---

## 4. Особенности работы

1. **Инициализация**: При запуске dumper сначала накапливает дельты обновлений, ждет полный Snapshot от биржи, синхронизирует их и только после этого начинает запись.
2. **Буферизация**: Данные записываются на диск батчами (по умолчанию по 5000 снимков), чтобы снизить нагрузку на IO.
3. **Безопасность**: При завершении работы (через `Ctrl+C`) dumper выполняет *graceful shutdown*, принудительно сохраняя остатки данных из буфера в файл.
4. **Логи**: Все события выгрузки записываются в `bots/FARTCOINUSDT/logs/dump.log`.
